# SIF 数据台 · 详细设计与可交互原型说明（v0.2）

> 配套总方案：[08-两条业务线整体设计方案](08-两条业务线整体设计方案.md)。
> 配套原型：[sif-ops-prototype.html](sif-ops-prototype.html)。原型全部使用**演示夹具**，不代表真实 ASIN、不代表已接通采集、不代表报告已能上架。
> 本文把设计落实到页面、字段、状态、接口、数据行、计算口径和测试用例。实施时若与本文冲突，先改设计再改代码。

## 1. 设计结论

产品不是一份报告生成器，而是一个**有证据链的优化工作台**：一个 ASIN 进入后，先形成产品族，再确认竞品，再采集事实，再形成可审计的改稿，最后以真实发布后的复测判断改稿是否有效。

两条业务线共用以下资产，但不共用结论：

- 共用：站点、ASIN 族谱、关键词、竞品集、CDP 快照、SIF 时序、政策规则版本、证据引用、报告导出。
- 不共用：存量线输出「逐字段改稿与复测」；新品线输出「方向选择与立项决策」。新品线不得把市场容量直接写成某个产品的预计销量。

### 1.1 现有资产核对结论

已读当前仓库并确认：

1. sif-ops 现有页面已有连接、对象、同步、看板、洞察、词库、竞品、优化 8 个页签；原型沿用暗色工作台语言，但新业务按工作流分组，不继续横向堆 14 个平级按钮。
2. amazon-ops 的 Amazon 页面读取已有标题、五点、图片、A+、评论摘要、变体与双 twister 布局；QA、品牌故事需新增读取器，不应声称现成。
3. amazon-ops 已有优化轮次、草案版本、发布登记、观测和轮次对比；本轮优先复用其版本与发布事实，不另造互相冲突的第二套主档。
4. 现有 `sif-ops/src/domain/listing-draft.js` 仍有事实回填风险：缺密度时会写 `75D`，缺形状时会写 `Rectangular`，并可能添加当前 Listing 未证明的结构/护理表述。**这些值不得进入新方案的可上架输出**，新方案使用「事实缺口 → 待确认」而非默认值补齐。

## 2. 信息架构与页面原型

### 2.1 导航结构

顶部固定「当前工作区 / 站点 / 当前产品族 / 数据截止 / 点数余额」，所有页面共享，避免跨 ASIN 张冠李戴。

| 导航组 | 页面 | 主要用户任务 |
|---|---|---|
| 工作区 | 总览 | 看进行中的优化、待确认竞品、待复测、数据缺口 |
| 存量优化 | 产品族 | 批量输入、展开主 ASIN 与子体、查看冲突 |
| 存量优化 | 竞品集 | 看候选来源、勾选、排除、确认版本 |
| 存量优化 | 采集中心 | 发起 CDP 与 SIF 补数、看分节状态与失败原因 |
| 存量优化 | 对照报告 | 逐字段原值/新值/理由/版本/政策状态 |
| 存量优化 | 复测闭环 | 发布登记、7/14/30 天节点、效果结论 |
| 新品调研 | 五阶段调研 | 容量、竞争、细分、验证、利润，阶段确认后推进 |
| 数据资产 | ASIN 管理 | ASIN 级 Listing 全字段、主/父/子体关系、添加父 ASIN、冲突与历史 |
| 数据资产 | 词库 / 市场 / 政策 | 查看现有 SIF 资产与规则出处 |

原型覆盖：ASIN 管理、产品族、竞品集、关键词总库与分析编排、采集中心、对照报告、复测闭环、数据来源与策略、新品调研九个核心页面；ASIN 详情有分节字段表与添加父 ASIN 表单，报告另有字段详情抽屉与历史版本切换。

### 2.2 关键交互

- 产品族：多行粘贴 ASIN → 校验格式 → 演示展开；父子树与维度冲突并列展示。
- 竞品集：候选按直接竞争/跨档标杆/品牌型分组；「确认本版」前显示选中数与排除数；确认后生成只读版本。
- 采集中心：CDP 与 SIF 分轨；每一节显示 collected / missing / failed / blocked / not_requested；不能把未采说成无内容。
- 对照报告：表格只展示摘要；点击行打开详情抽屉，显示完整前后值、证据、事实边界、政策校验与改动幅度。
- 历史版本：选择本轮、上一轮、上上一轮；切换后表格显示该版本完整快照，不把历史字段与当前字段混排。
- 复测：指标显示基线、当前值、差值、数据状态；环境变化单独标识，避免归因给改稿。
- 新品调研：五阶段纵向步骤条；当前阶段可编辑，未来阶段锁定；完成确认后解锁下一阶段。

### 2.3 报告字段排序

固定顺序，保证不同轮次可对比：

1. 标题；2. Item Highlights；3. 五点 1–5；4. 产品描述；5. 主图；6. 副图 1–6；7. 视频；8. A+ 各模块；9. 品牌故事；10. Search Terms；11. 评论答疑转化；12. 属性逐键；13. 变体结构；14. 价格；15. GEO 问答覆盖；16. 政策合规说明。

「评论」不是可被上架改写的字段，报告输出的是**由评论证据支持的文案/图片/产品改进项**；评论原文只读，不伪造回复或评论。

## 3. 核心领域对象与不变量

### 3.1 对象关系

```text
Family（marketplace + parentAsin）
 ├─ FamilyMember（childAsin + dimensions）
 ├─ CompetitorSet(version) → CompetitorMember[]
 ├─ CollectionRun → CollectionSection[] + Snapshot[]
 ├─ OptimizationRound(version) → FieldChange[]
 │    └─ PublicationRecord → ObservationPlan → Observation[]
 └─ EvidenceRef[]（被 FieldChange、市场结论、复测结论共同引用）
```

### 3.2 不变量

1. 族键为 `(marketplace, parentAsin)`，无父体时使用自身 ASIN 并标 `familyType=single`，不得伪造 parent。
2. 同族成员键唯一；变体维度坐标相同不自动合并；一子多父记冲突。
3. 竞品集每次确认新增版本，旧版本不改；报告绑定 `competitorSetId`。
4. 改稿记录不可变；同一优化轮次重新编辑生成新草案版本，发布必须绑定被接受的草案版本。
5. 一个字段的证据至少一条；没有事实支持的规格不得进入「可上架」状态。
6. 报告的原值来自**本轮冻结快照**，不是打开页面时重新读取的最新值。
7. 历史版本比较必须比较同 `fieldKey`、同 ASIN、同站点；父体和子体不得混排。
8. 复测的基线是发布前冻结快照；当前值来自对应节点采集。缺数据结论是 `insufficient`，不是 `unchanged`。
9. 政策规则无来源/版本/适用范围时禁用；`block` 未清零不得显示「可直接上架」。
10. 原始 HTML、截图与图片文件是本地文件引用；数据库保存路径、哈希和元数据，不把大二进制塞入 SQLite。

## 4. 字段级设计

### 4.1 统一字段键

| 字段键 | 类型 | 原值来源 | 优化输出 | 上架边界 |
|---|---|---|---|---|
| `title` | string | CDP | 完整标题 | 规则无 block 且事实齐全 |
| `item_highlights` | string/string[] | CDP，无区域则 missing | 完整亮点 | 无区域不能写成「原无亮点」 |
| `bullet_1..5` | string | CDP | 每条完整文案 | 每条一主题，事实可追 |
| `description` | string | CDP | 完整描述 | 无来源事实待确认 |
| `image_main` / `image_1..6` | asset | CDP 图片区 + 图像元数据 | 拍摄/设计脚本 | 不生成图片本体 |
| `video` | asset | CDP 视频区 | 分镜脚本 | 无视频 ≠ 采集失败 |
| `aplus.<moduleId>` | module[] | CDP A+ | 模块类型、文案、图脚本 | 无后台写权限，不自动上架 |
| `brand_story` | module | 新 CDP 读取器 | 品牌故事文案与图脚本 | 无品牌资料不得编造 |
| `search_terms` | string | 人工/后台导出 | 去重后的后台词 | 前台不可见，需明确来源 |
| `attribute.<normalizedName>` | key-value | CDP 属性区 | 完整属性值 | 未知事实标待确认 |
| `variant.structure` | tree | twister | 结构建议 | 不自动改变体关系 |
| `price` | money | CDP + SIF 快照 | 建议区间/测试价 | 需结合真实成本 |
| `geo.<questionId>` | answer block | QA/五点/属性证据 | 可引用的问答句 | 结论需事实支撑 |

### 4.2 字段状态

`unchanged`（有值且无需改）/ `proposed`（有新值）/ `needs_fact`（缺事实）/ `blocked`（政策或权限阻断）/ `no_source`（本系统无来源）/ `not_applicable`（该品类/对象不适用）。

**空字符串不能同时表示这六种状态。** 页面显示中文标签，接口保留机器码。

### 4.3 优化理由结构

每条理由不是一段不可验证的散文，而是以下四部分的组合：

1. 差距：我的值与竞品中位数/标杆的具体差异。
2. 证据：引用词、竞品、评论/QA、页面属性或政策规则。
3. 改动：说明新增、删除、移位、重写分别改了什么。
4. 边界：样本范围、缺失数据、需要人工确认的事实。

## 5. 采集与证据设计

### 5.1 采集批次

`CollectionRun` 记录对象范围、站点、方案版本、开始/结束、状态与请求人；每个 ASIN 的每个 section 单独记录状态。批次失败不清空已采内容。

### 5.2 Section 清单

`basic / bullets / highlights / images / variations / attributes / description / aplus / brand_story / video / reviews / qa / related_competitors / seo_meta / bsr / page_signals`

- `not_requested`：本次未请求。
- `missing`：页面明确没有该内容。
- `failed`：选择器或读取失败，不能判断有没有。
- `blocked`：验证码、登录墙或访问限制。
- `partial`：只采到一部分，例如评论仅游客可见样本。

### 5.3 选择器与漂移

复用 amazon-ops 的候选选择器与 `page_region` 记录法。新 QA/品牌故事读取器先用真实页面建立 fixture；一节渲染但标题等结构字段为空，按选择器失败处理，不按无内容处理。

### 5.4 图片和 A+

- 记录 URL、顺序、alt、图片像素、文件哈希、本地路径。
- 白底与像素规则只有在实际图像检查后才给通过；有 URL 不等于合规。
- A+ 按模块保存 `moduleType / text / imageRefs / order`；纯文本覆盖不能证明视觉质量。

### 5.5 证据引用

```json
{
  "kind": "sif_keyword | cdp_field | competitor | review_sample | qa | policy | human",
  "ref": "本地记录或文件 ID",
  "observedAt": "实际观测时间或 null",
  "dataDate": "SIF 数据截止日或 null",
  "sample": "评论/QA 样本量等",
  "note": "适用范围与限制"
}
```

未注明时间的证据必须显示「未注明时间」，不能默认成「刚刚」。

## 6. 竞品与对比计算

### 6.1 候选归并

同一 ASIN 多来源合并，保留全部来源；去重键 `(marketplace, asin)`。候选分值只用于排序，不作为「好坏」事实：SIF 份额、ABA Top3、页面关联位分别展示。

### 6.2 分档与中位数

- `direct`：默认进入竞品中位数。
- `benchmark`：只进入标杆对比，不进入中位数。
- `brand`：单独展示，不作为机会词。
- `excluded`：保留排除理由，不删除。

样本量 `n` 必须显示；`n < 3` 时中位数只作参考，报告标「样本不足」。无价格/评分等字段的行不进入该指标分母，不得按 0 参与。

### 6.3 字段对比

文本字段不只比较长度：关键词覆盖、属性事实、卖点主题、QA 问题覆盖分别列出。图片/A+ 比较只声明可验证的结构差异，不从截图推断转化率。

## 7. 改稿、版本与发布状态机

### 7.1 优化轮次

```text
draft → evidence_ready → generated → validating → ready_for_review
      → accepted → published → observing → completed
```

异常状态：`needs_fact / blocked / failed / abandoned`。`accepted` 后如需修改，创建新草案版本，不覆盖已接受版本。

### 7.2 「可直接上架」判定

只有同时满足以下条件才显示：

- 字段级政策校验无 block；
- 所有规格与事实有证据或人工确认；
- 关键词来源与适用范围已记录；
- 文本在字段预算内，图片字段明确是脚本而非已制作素材；
- 策略与改动范围已经人工接受。

「系统校验通过」不等于 Amazon 实际上架成功，后者只能由发布登记证明。

### 7.3 版本展示

每轮字段行包含 `roundId / draftVersion / fieldKey / before / after / reason / evidence / verdict / createdAt`。历史下拉只列实际存在的最近两轮；不足两轮时明确显示「无更早版本」，不复制当前版本充数。

### 7.4 发布登记

登记实际发布字段、实际值、时间、操作人和草案版本。实际值与接受稿不一致时记 `deviated`，由人决定重新观测或记为误发布。系统不调用卖家后台发布。

## 8. 复测闭环详细口径

### 8.1 节点与指标

节点默认发布后 7/14/30 天。指标：流量总分、自然流量、广告流量、自然占比、目标词自然位、BSR、评分、评论数、价格。无来源指标显示「无来源」，不显示 0。

### 8.2 数据状态

每个节点先判断窗口是否有完整数据：SIF 最后点未出完、CDP 被拦、目标词未扫描，均不能直接给有效/无效结论。

### 8.3 结论

- `keep`：预设核心指标改善且未出现失败指标恶化。
- `watch`：方向不一致、样本不足或环境变化。
- `revise`：需要继续改稿，列出依据。
- `rollback`：达到预先登记的回滚条件。
- `insufficient`：数据不足，不给业务效果结论。

阈值在发布前写入观测计划；不能看到结果后再调阈值。流量变化不自动等于销量/转化改善，广告花费与 ACOS 无后台报表时明确缺失。

## 9. 新品调研线详细设计

| 阶段 | 输入 | 分析 | 输出/阶段门 |
|---|---|---|---|
| 1 市场容量 | 站点、非品牌词根、上线准备周数 | 精确词与词根规模、趋势、季节性 | 容量区间与口径；确认后进入 2 |
| 2 竞争格局 | 阶段 1 的词 | 集中度、头部强度、价格/评论门槛 | 竞争门槛；确认后进入 3 |
| 3 长尾与细分 | 词根关系词 | 需求分布、候选细分 | **人选一个方向** |
| 4 画像与竞品验证 | 选定词、产品画像 | 画像作筛选条件、对标竞品、属性差距 | 对标集与可行性；确认后进入 5 |
| 5 利润与推广 | 售价、成本、头程、毛利率、尺寸重量 | 采购上限、CPC/CVR 盈亏、推广可行性 | 立项决策卡 |

决策卡固定包含：建议（继续/补数/暂缓）、理由、已排除方向、关键假设、未决事实、预算与点数消耗。供应链、合规、专利和真实经营数据未核实不得写「确定可立项」。

## 10. 数据表与内部接口

### 10.1 表职责

总方案 9 张新增表保留，实施时补充以下约束：

- `sif_family_member`：唯一键 `(family_id, asin)`；坐标哈希仅用于查重，不作为合并依据。
- `sif_competitor_set`：唯一键 `(family_id, version)`；`confirmed_at` 之前不可被报告引用。
- `sif_cdp_snapshot`：唯一键 `(marketplace, asin, section, captured_at, content_hash)`；保存 `status` 与 `page_region`。
- `sif_optimize_round`：保存 `baseline_snapshot_id / competitor_set_id / policy_version / prompt_version`。
- `sif_field_change`：唯一键 `(round_id, draft_version, field_key)`；`before/after` 使用 JSON 以容纳文本、模块和资产。
- `sif_publish_record`：保存 `draft_version / published_json / deviation_json`。
- `sif_observation`：唯一键 `(publish_id, node_day)`；保存 `data_status / verdict / baseline_metrics / current_metrics / environment_flags`。
- 新增 `sif_research_run` 与 `sif_research_stage`：保存五阶段输入、证据、确认人和确认时间。
- 新增 `sif_evidence`：统一证据索引，避免理由里塞不可检索的长 JSON。

### 10.2 页面 JSON API（同源、只读优先）

| 方法与路径 | 用途 | 失败语义 |
|---|---|---|
| `POST /api/families/expand` | 多 ASIN 展开族谱 | 逐对象结果，部分失败不抹掉成功项 |
| `GET /api/families/:id` | 族谱、冲突、完整度 | 无族与无变体分别返回 |
| `POST /api/competitors/discover` | 生成候选， dryRun 报预算 | 配额不足不生成假空集 |
| `POST /api/competitors/confirm` | 确认新版本 | 空集需明确原因，不默认通过 |
| `POST /api/collection/run` | 创建 CDP 采集批次 | 环境失败/被拦分类 |
| `GET /api/collection/:id` | 批次与分节进度 | 保留已采行 |
| `POST /api/rounds` | 基于快照与竞品集建优化轮次 | 缺竞品确认或基线则拒绝 |
| `POST /api/rounds/:id/validate` | 规则、事实与覆盖校验 | block/warn 分开 |
| `GET /api/rounds/:id/report` | 对照表与视角数据 | 无草案与草案为空分别返回 |
| `POST /api/publications` | 人工登记实际发布 | 版本不匹配拒绝 |
| `GET /api/observations` | 节点、基线、当前值、结论 | 缺数据不当作无变化 |
| `POST /api/research` / `POST /api/research/:id/confirm` | 调研与阶段确认 | 未确认不得跳阶段 |

### 10.3 Agent 工具

新增工具只编排已有领域函数，不复制业务逻辑：

`sif_family_expand / sif_competitor_candidates / sif_competitor_confirm / sif_collect_page / sif_optimize_round / sif_field_report / sif_observe / sif_research_stage`。

所有读操作 0 点；只有显式同步/发现动作调 SIF。任何工具不自动发布。

## 13. 官方五份手册 → 关键词总库与分析能力映射

> 本节依据 [07-官方手册模块拆解](07-官方手册模块拆解.md) 与当前 SIF MCP 工具面。官方折叠块未读到的细节不冒充已读；这里设计的是模块编排，具体阈值须以实际工具返回与政策来源验收。

### 13.1 五份手册在系统里的位置

| 官方手册 | 系统化模块 | 不能只做成的样子 |
|---|---|---|
| 初阶：准备、客户端、开发/运营视角、FAQ | 连接、权限、点数、数据新鲜度、使用引导 | 一个只显示「连接成功」的设置页 |
| 中阶 Part1：关键词与需求发现 | 关键词总库 + 市场容量/生命周期/时机分析 | 一张只按搜索量排序的词表 |
| 中阶 Part2：市场竞争与竞品筛选 | 市场格局 + 竞品候选/确认 + ASIN 卡位地图 | 只列 Top ASIN，没有分档与证据 |
| 中阶特色：成本与利润 | 新品阶段 5 的利润与推广经济模型 | 用市场参考值冒充真实净利润 |
| 中阶 Part3/4/5 | Listing 定位、广告结构、上线后诊断 | 官方网页无正文的部分不编造场景细节 |
| 高阶 4 Skill | 四条可复用分析编排，不是四个孤立按钮 | 不读本地证据、每次从头乱调工具 |
| 五阶段提示词 | 新品线阶段状态机与点数预算 | 一把梭生成完整立项报告 |
| 标题新规报告 | 存量改稿的词组优先级表、对照报告、透明度声明 | 只给新标题，不给原词去向与依据 |

### 13.2 关键词总库：一词多身份，不靠覆盖状态

沿用 `sif_keyword`、`sif_keyword_aba`、`sif_keyword_demand`、`sif_asin_keyword`，新增**身份与用途层**，不把状态直接写死在词主表：

| 维度 | 取值/内容 | 用途 |
|---|---|---|
| 词身份 | `candidate / tracked / excluded` | 挖来待定、正在追踪、明确排除；候选不进正式报告 |
| 需求身份 | 精确词 / 词根变体 / 下拉联想 / 词组关系 | 保留 SIF 来源关系，避免不同关系混成一词 |
| 市场身份 | 增长 / 稳定 / 回暖 / 衰退 / 待判断 | 来自需求诊断，不能凭一周变化推断 |
| 业务身份 | 核心词 / 场景词 / 属性词 / 品牌词 / 竞品词 | 品牌词与竞品词单独隔离 |
| 我的位置 | 有排名 / 测过未出现 / 未测量 | 三种状态分别保存 |
| 建议用途 | 标题 / 五点 / 后台 / 广告精确 / 广告词组 / 否定候选 | 是建议，不是实际上线事实 |
| 证据与时间 | 来源工具、数据周、抓取时间、扫描深度 | 无时间的值不得显示成最新 |

**总库不是词越多越好**：每个词都要能回答「从哪里来、哪个站点、哪个市场周、我是否测过、能用于哪里、为什么不能用于哪里」。

### 13.3 词库生产与分析链

```text
CDP 标题/五点/属性/QA + 自有 ASIN 词 + 竞品词 + 非品牌词根
  → 规范化与去重 → SIF 词根机会挖掘 → 候选词库
  → ABA 周量/点击与转化集中 → 需求趋势/生命周期 → 我的排名/流量份额
  → 竞品覆盖与卡位 → 人工确认 tracked/excluded
  → 标题/五点/后台/广告用途建议 → 改稿与报告
  → 发布后节点复测 → 保留/继续改/回滚证据
```

| 分析模块 | 输入 | 工具/本地数据 | 输出 |
|---|---|---|---|
| 机会筛选 | 词根、站点 | `sif_mine` / `market_screen_keyword_opportunities` | 候选词、周搜索量、关系类型、来源 |
| 市场容量 | 精确词+词根 | `market_get_keyword_root_trend` + ABA 历史 | 精确量/词根量、趋势、分布，不合成月量 |
| 生命周期与时机 | 核心词组 | `market_get_keyword_demand` | 长期/近期趋势、季节性、距高点、待判断 |
| 竞争可进入性 | 核心词 | `sif_competition` / `market_get_keyword_competition` | 集中度、头部份额、Top 竞品、我的位置 |
| 竞品格局与筛选 | 候选竞品池 | `market_discover_competitors`（按官方前置链） | 价格/评论/销量档位/姿态分布与分档 |
| ASIN 卡位地图 | 自有/竞品 ASIN | `market_get_asin_aba_footprint` | 该 ASIN 在哪些词 Top1/2/3，发现词根外覆盖 |
| 自有词诊断 | 我的 ASIN | `market_get_asin_keyword_signals` | 词贡献、自然/广告依赖、排名变化与健康度 |
| 广告结构 | ASIN/活动/广告组 | `ads_get_asin_ad_structure` → campaign → ad group → keyword | 结构变化、贡献与词分布；**不含 ACOS/订单效果** |
| 利润与推广 | 词、售价、成本、尺寸重量 | `market_assess_keyword_promotion` + `market_estimate_profit_threshold` | 盈亏门槛与采购上限，标明市场参考值 |
| 改稿词组去向 | 原标题词组+总库 | 本地分析 | 保留/前移/改写/删除/转后台/转广告及理由 |

### 13.4 高阶 4 Skill 的系统编排

| Skill | 编排顺序 | 停止/转人工条件 |
|---|---|---|
| 市场机会 × 产品可行性 | 词库候选 → 容量 → 生命周期 → 竞争 → 利润 | 数据未覆盖、成本缺失、方向未由人选定 |
| 竞品流量 × 广告策略解剖 | 确认竞品 → ABA 卡位 → 词信号 → 广告结构下钻 | 竞品未确认、不同周期两侧数据禁止直接比较 |
| 产品利润 × 推广经济模型 | 产品事实 → 推广词经济 → 佣金/FBA → 采购上限 | 尺寸重量/头程/毛利缺失，不猜值 |
| 流量诊断 × 增长修复 | 流量窗口 → 词贡献 → 竞争/需求排除 → 广告结构 → 复测 | 未出完的数据点、无排名观测、无效果数据不下确定结论 |

这些编排由页面任务与 Agent 工具共用同一个领域服务；不在 UI 和 Agent 各写一套结论规则。

### 13.5 标题新规手册进入对照报告的方式

在现有六列对照表前增加可展开的「标题词组优先级表」：

`原词组 / 类型 / 对应关键词 / 周搜索量 / 我的自然位 / 需求趋势 / 竞品覆盖 / 优先级 / 最终去向 / 证据`。

最终去向必须是封闭词表：`keep / move_front / rewrite / remove / backend / ads / undecided`。标题改稿因此能解释每一个重要原词去了哪里，而不是只展示新旧标题。

## 14. 数据质量与分析口径闸门

| 闸门 | 通过条件 | 未通过时的系统行为 |
|---|---|---|
| 时间对齐 | 两侧周期一致或明确标注不同 | 禁止直接给竞争胜负结论 |
| 扫描深度 | 「未出现」有扫描页数/深度 | 显示未测量或覆盖不足，不写没有排名 |
| 销量口径 | 保留前台档位文本 | 禁止换算成精确值参与利润计算 |
| 搜索量口径 | 周/月字段分开 | 禁止周量 ×4 当月量 |
| CTR 口径 | 整体搜索点击率与 Top3 集中度分开 | 缺 CTR 显示未知，不显示 0 |
| 竞品版本 | 已确认版本且分母明确 | 候选池不进入中位数 |
| 产品事实 | 当前 ASIN 证据或人工确认 | `needs_fact`，禁止行业默认值回填 |
| 广告效果 | 有后台报表才计算 ACOS/CVR/订单 | 只做结构诊断 |
| 复测数据 | 节点到期且数据完整 | 缺数据只能 `insufficient` |

## 15. 数据来源分级、分析策略与证据链

### 15.1 数据来源全景

系统对每条数据同时保存「谁提供 / 怎么取得 / 什么时候观测 / 数据本身截止何时 / 适用范围 / 有什么缺口」。来源不是页面上的一个图标，而是结论能否成立的输入。

| 来源层 | 数据 | 采集/工具 | 可回答 | 不能回答 |
|---|---|---|---|---|
| Amazon 前台事实 | 标题、五点、价格、评分、变体、属性、图/A+、品牌故事、QA、游客可见评论 | CDP 浏览器逐页采集 | 当时页面展示了什么 | 真实库存、真实订单、后台未公开字段 |
| SIF 流量域 | 流量分、自然/广告渠道、排名与词级变化 | `ops_*` | 流量在什么时间、哪个词、哪个渠道变化 | 真实销售额、转化率、流量分的绝对人数 |
| SIF 市场域 | ABA 搜索量、需求、竞争、竞品、卡位 | `market_*` | 市场需求、集中与卡位、竞品格局 | 我账号的真实经营结果 |
| SIF 广告结构域 | Campaign/广告组/关键词、曝光贡献、结构变化 | `ads_*` | 广告结构怎样搭、流量从哪来 | 花费、ACOS、CVR、订单 |
| 人工与后台资料 | 成本、尺寸、Search Terms、广告报表、政策原文、发布事实 | 人工补录/文件导入 | 私有事实和实际经营数据 | 未提供内容不得推断为已知 |
| 派生分析 | 中位数、词覆盖、优先级、改稿、复测结论 | 本地规则与 Agent | 在明确口径下的建议 | 不是新的原始事实 |

### 15.2 证据强度与冲突处理

| 级别 | 证据 | 使用规则 |
|---|---|---|
| A · 事实 | 当前 ASIN 的 CDP 字段、人工确认资料、后台导出 | 可用于规格和上架文案；仍需时间与适用范围 |
| B · 平台/市场观测 | SIF 流量、ABA、广告结构 | 可用于趋势与市场判断；必须带周期和口径 |
| C · 竞品/样本信号 | 竞品文案、游客评论、QA、关联位 | 用于发现假设和差距，不当作我的产品事实 |
| D · 推断 | 本地评分、优先级、Agent 文案 | 必须引用 A/B/C，标为建议 |

冲突时不静默选值：例如 CDP 与人工规格不一致，显示两个值及来源，状态为 `needs_fact`；只有人工确认可改变采用值。竞品规格永远不能覆盖我的规格。

### 15.3 统一证据记录与结论格式

```text
原始证据 Evidence
  → 归一化事实 Fact（对象、字段、值、来源、观测时间、数据截止）
  → 分析 Finding（对比口径、计算过程、样本量、限制）
  → 决策/改稿 Action（改动、理由、证据引用、政策校验）
  → 发布事实 Publication（实际值与草案版本）
  → 复测结论 Observation（基线、当前值、环境变量、结论）
```

每个结论必须返回：`claim / evidenceRefs / analysisStrategy / scope / period / sampleSize / missing / confidence / residualUncertainty`。
`confidence` 不凭空给百分比，使用有依据的「充分 / 有限 / 不足」；无法判断时结论就是「无法判断」。

### 15.4 分析策略库（页面与 Agent 共用）

| 策略 | 分析顺序 | 输出要求 |
|---|---|---|
| 关键词机会 | 词根关系 → 周需求 → 生命周期 → 我的测量 → 竞品卡位 → 用途 | 候选与正式词分离；标来源和扫描深度 |
| 竞品优缺点 | 确认竞品版本 → 同字段同周期 → 我/中位数/标杆 → 样本与缺口 | 不将竞品规格当我的事实；显示分母 |
| Listing 改稿 | 冻结原值 → 词组去向 → 事实校验 → 改稿 → 政策与覆盖校验 | 每字段有理由；缺事实待确认；图只出脚本 |
| 流量异常 | 先找窗口 → 拆渠道 → 拆词 → 排除需求/竞争/广告 → 修复 | 不允许「可能竞争加剧」直接作结论 |
| 广告结构 | ASIN 总览 → 活动 → 广告组 → 关键词/变体 | 只谈结构与曝光；无报表不判断 ACOS |
| 新品立项 | 容量 → 竞争 → 人选细分 → 画像校验 → 利润与推广 | 每阶段确认；保留假设与残余风险 |
| 发布复测 | 冻结基线 → 实际发布 → 同口径节点 → 环境变量 → 结论 | 无数据=数据不足；流量改善≠销售改善 |

### 15.5 报告必须呈现的「分析过程」

对需求方、老板和客户三种视角，均保留可展开的同一份过程，不靠隐藏证据让报告变短：

1. 本轮对象、主/子 ASIN、站点、竞品集版本、政策版本。
2. 数据源清单、各数据截止日、CDP 分节覆盖、SIF 工具清单与点数。
3. 差距计算：对比池、分母、中位数/标杆、缺失值处理。
4. 改稿理由：词组去向、事实依据、政策结果、待确认事实。
5. 未采用方案与排除原因（例如某竞品因跨档只做标杆）。
6. 复测计划与预设阈值；环境变量和不能判断的指标。
7. 透明度声明：样本、缺口、AI 建议边界、是否实际发布。

### 15.6 点数与数据复用策略

- 先读本地库和快照，再决定缺什么；分析重跑不重复扣点。
- CDP 可取得的页面事实不花 SIF 点。
- SIF 调用按批次预算，记录预计/实际扣点与余额；配额不足时不以空结果冒充市场不存在。
- 报告绑定证据快照，后续数据更新不篡改历史报告；新一轮分析产生新轮次。

## 16. ASIN 管理模块（主档 + Listing 全字段 + 关系维护）

### 16.1 职责与术语

ASIN 管理是**对象主档与关系入口**，产品族页是批量任务入口，两者不重复：

- **主 ASIN**：本项目对一个产品族选定的主要运营对象，用于默认看板、报告与同步。它是业务选择，不必然是 Amazon 的技术父体。
- **父 ASIN（parent ASIN）**：Amazon 变体关系的父体，通常不可直接购买；前台数据可能缺价格/排名，不能把缺值当 0。
- **子体/变体 ASIN**：实际可售的颜色、尺寸等具体商品；标题优化默认以子 ASIN 为单位，避免不同变体混改。
- 无变体商品标 `single`；主 ASIN 可等于该单品自身，但不伪造 Amazon 父体关系。

### 16.2 ASIN 列表

| 列 | 说明 |
|---|---|
| ASIN / 缩略图 / 标题 | 点击 ASIN 进入该对象详情 |
| 角色 | 主 ASIN、父 ASIN、子体、单品；角色可组合，如「主 ASIN · 子体」 |
| 主 ASIN / 父 ASIN | 分开两列，禁止用一个字段混装两种关系 |
| 变体坐标 | 颜色、尺寸等维度值；无值显示未采集 |
| 价格 / 评分 / 评论 / BSR | 附数据时间；无来源不显示 0 |
| 数据完整度 | 已采节数/请求节数，无请求不显示 0% |
| 关系状态 | 正常、待确认、冲突、已纠正 |
| 最近采集 / 操作 | 采集、查看详情、设为主 ASIN、编辑关系 |

支持按站点、归属（我的/竞品）、角色、父 ASIN、关键词/ASIN、数据缺口筛选。批量操作只允许添加入库与创建采集任务；不设主 ASIN、不改关系这种判断性操作逐条执行并留原因。

### 16.3 ASIN 级 Listing 全字段详情

详情页头部固定显示：当前 ASIN、角色、主 ASIN、父 ASIN、全部兄弟变体、数据完整度、最近采集时间。正文分节如下：

| 分节 | 字段与操作 |
|---|---|
| 基础与分类 | 标题、品牌、类目、价格/币种、评分/评论数、BSR、上架日、库存页面信号 |
| 文案 | Item Highlights、五点逐条、描述、Search Terms（人工/后台来源） |
| 视觉与视频 | 主图、副图逐张、URL/alt/像素/顺序、本地预览、视频与脚本 |
| A+ 与品牌故事 | 模块顺序、模块类型、每段文案、图片与原始快照 |
| 属性 | 页面全部键值、标准化属性名、原属性名、来源区域、竞品差异 |
| 变体关系 | 主/父/子体、维度坐标、兄弟变体、重复坐标、一子多父与纠正历史 |
| 评论与 QA | 游客可见样本、问题与回答、样本量、采集范围；不提供伪造互动 |
| 流量/关键词/广告 | 当前 ASIN 的 SIF 词、排名、流量与广告结构；父体聚合和单 ASIN 口径分开 |
| 优化与历史 | 对照报告、草案版本、实际发布值、观测节点；原始值/接受稿/发布值分开 |
| 来源与原始快照 | 每个字段的来源、采集时间、数据截止、page region、HTML/截图/图片引用 |

字段显示三态必须区分：**页面无此内容 / 本次未采集 / 本系统无来源**。原始快照只读；人工修正写为新采用值，不改历史采集值。

### 16.4 添加与维护父 ASIN

表单字段：站点、子 ASIN、要添加的父 ASIN、变体维度（可选，未知则不填）、来源（CDP/人工/导入）、证据（页面 URL/文件）、原因、操作人。

规则：

1. ASIN 格式为 10 位字母数字，统一大写；父与子不能相同；父体/子体必须同站点。
2. 未采集过的父 ASIN 可先建立占位主档，状态为 `unverified`，随后创建采集任务；不伪造标题和价格。
3. 同一子体被添加到第二个父体时**保留候选关系并标冲突**，不静默覆盖；由人决定采用/纠正哪条。
4. 重复坐标、父子循环、把当前子体作为自己的父体均阻止或标冲突；不因人工录入就绕过校验。
5. 设错关系使用「纠正」：旧关系保留、状态改 `corrected`、记录原因与证据；不物理删除历史。
6. 「设为主 ASIN」只改变本项目的运营默认对象，不修改 Amazon 父子关系，也不触发发布。
7. 有正在运行优化/观测的对象改关系时，显示受影响轮次，要求明确确认；历史报告继续绑定旧快照。

### 16.5 数据落点

优先复用 amazon-ops 已验证的 `variant` 关系、维度、纠正历史与 ASIN 主档；sif-ops 保存运营侧的 `is_primary / family_role / collection coverage` 引用，**不复制第二套父子事实**。

sif-ops 新增/扩展：

- `sif_asin_role`：`(marketplace, asin, is_primary, ownership, note, updated_at)`；`is_primary` 只表达运营主对象。
- `sif_asin_coverage`：按 ASIN 与采集批次派生各 section 状态，页面不自行计算另一套口径。
- amazon-ops 关系不可用时，页面明确显示「关系服务不可用」，不降级为把所有 ASIN 当单品。

### 16.6 接口与测试补充

接口：`GET /api/asins`（筛选列表）、`GET /api/asins/:asin`（全字段详情）、`POST /api/asins`（添加入库）、`POST /api/asins/:asin/primary`（设运营主对象）、`POST /api/asins/:asin/parent`（添加父关系）、`POST /api/asins/:asin/relation/correct`（纠正关系）。写操作均留审计，不向 Amazon 发布。

测试新增：

- U16：主 ASIN 与父 ASIN 分字段保存，读详情不串值。
- U17：添加未采父 ASIN 只建 unverified 占位，字段不虚构。
- U18：一子多父与重复坐标保留并提示冲突，不覆盖。
- U19：父子同值/跨站点/循环关系被拒绝或明确冲突。
- U20：纠正关系后历史仍可查，当前冲突按状态消失。
- U21：单品、父体缺价格、未采集与无来源在 UI 分别显示。
- U22：改主 ASIN 不改父体、不发布、不改写历史报告。
- 原型：角色筛选、详情分节、添加父 ASIN 的非法输入与成功反馈实际点击验证。

每一期同时交付：迁移、领域函数、页面、Agent 工具、单元/集成测试、真实 ASIN 验收记录。上一期验收未过，不进入下一期。
