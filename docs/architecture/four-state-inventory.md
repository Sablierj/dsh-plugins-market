# 四态空态 · 核实结论（P3-1 收尾）

> **结论先说：逐个核实下来，没有发现需要补的四态缺口。**
>
> 也就是说 P3-1 的真实答案是「这块已经做到了」，而不是「还差 14 个页签」。
> 本页记录**核实过程**、**证据行号**，以及**我三次误判的原因**——
> 因为三次都是同一个毛病：机械判据代替了读代码。

## 1. 核实的三种方法，前两种都失效了（记下来避免重犯）

| # | 方法 | 为什么失效 |
|---|---|---|
| 1 | 按固定词表 grep（`no-source` / `not_modelled` / `unsourced` …） | 这个库用**每个模块自己的措辞**表达同一件事，词表命中数会系统性低估 |
| 2 | 扫 `/api/state` 的 payload 形状，空数组/0/null 就算缺口 | ①`/api/state` **按当前模块按需下发**，没选中的切片全是 `null`；②更糟的是我用的「切片→页签」映射是**猜的**，`asin.js:829` 证明 `keywords` 键其实是 ASIN 详情用的 |
| 3 | **真机点每个页签，抓用户实际看到的空态文案** | ✅ 这个有效 |

第三种之所以有效：**用户看到的那句话不会骗人**。

## 3. 「暂无」不是缺口 —— 它旁边有分子分母

`src/domain/dashboard/health.js:41`：`EMPTY_CONCLUSION = '暂无数据'`

`src/domain/dashboard/health.js:86`：空的时候用它当结论。

`src/web/pages/home.js:39-41`：卡片同时画 `card.numerator / card.denominator`。

`src/web/pages/home.js:64`：状态三态 `error`（计算失败）/ `empty`（暂无数据）/ 正常。

`src/web/pages/home.js:616` 的注释把语义写死了：

> 「暂无」is a kind **whose table exists and has no rows**（表存在、但没有行）

所以首页的「暂无」= **读到了、答案是 0**，而且旁边有 `0 / 0` 与状态标。**分得开，只是文案短。**

## 4. 我最初判成「缺口」的两类，其实都不是

1. **「先在 ASIN 列表里选一个我们的 ASIN」**（competitor）—— 这是**操作指引**，
   不是"数据缺失"。把它算缺口是把「没选对象」误当成「没数据」。
2. **裸 `null` 切片**（`kw` 的 `keywords`/`coverage`）—— payload 层裸奔，
   但页面拿到 null 时画的是**引导文案**（见 §2 的 research/policy 行），不是空白。
   我先前只看 payload 就判缺口，等于「用接口形状推断用户体验」。

## 5. 所以 P3-1 的最终答复

- **不需要新增四态代码。** 现有实现已经覆盖：`optimize` 的十类证据有
  `frozen / absent / not_modelled` 闭集且「读到 0」用 `frozen + count: 0` 表达
  （`tests/b13b` ⑫⑬ 钉住）；首页有 `EMPTY_CONCLUSION` + 分子分母 + 三态状态；
  其余页签的空态文案都写明了「还没有 / 还没跑 / 库是空的」以及**下一步怎么做**。
- **真实的可改进点只有一条**（不是我原来想的"补缺口"）：
  多数空态文案是「还没有 X + 怎么做」，只有 `report` 和 `optimize` 两处
  **显式排除了误读**（「这不是『没有数据』」「这不代表没改过」）。
  其余页面缺这一句 —— 对老手无所谓，对新人就是"到底是没有，还是坏了"。
  如果要统一，那是**文案润色**（低风险、逐条改），不是四态能力问题。

## 6. 证明不了什么

- 本页只核实了**空库**下的空态。**有数据但筛出 0 条**（「筛选太窄」那一态）
  只有 `collect` 的一条计划文案提到过，其余页签**没有验**。
- 真机抓的是 `.empty` 元素；如果某个页签把空态写在别处（例如 `hint`/`muted`），
  本页会漏掉。§2 的「能否分辨」列是按抓到的原文判的，不是按设计文档。
