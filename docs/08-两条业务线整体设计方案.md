# SIF 数据台 · 两条业务线整体设计方案（v0.1）

> 需求方拍板口径（2026-11-05）：
> ① 竞品集 = 自动选完由需求方确认；② 报告给自己/老板/客户，要有理由和分析过程，覆盖标题、亮点、五点、主副图、A+、评论、结构、变体、GEO、价格、所有属性与品类政策；
> ③ 文案要到可直接上架；④ 要复测闭环；⑤ 输入一份多 ASIN 列表，自动拉变体与主 ASIN、找竞品，原始数据走 CDP 采集；
> ⑥ 最终报告是**逐字段对照表**（序号 / 属性字段 / 原值 / 优化后值 / 详细理由 / 近两个版本可切换），全部集成进 SIF 数据台。
> 本轮只出设计，不写代码。

---

## 0. 一句话

把 sif-ops 从「数据台」升级成**两条业务线的工作台**：**存量优化**（改到能上架、改完能证明）和**新品调研**（从词到立项决策卡）。底层共用对象、快照、口径、报告四套资产，流程各自独立。

---

## 1. 业务线与运行边界

### 线 A · 存量 ASIN 优化（主流程）

```
输入 ASIN 列表 → 族谱展开（主 ASIN + 全部子体）→ 竞品自动候选 → 需求方确认竞品集
  → CDP 采我自己 + 竞品 → SIF 补市场/流量/广告 → 逐字段差距 → 改稿 + 理由
  → 政策校验 → 对照报告 → 人工发布登记 → 7/14/30 天复测 → 效果结论 / 回滚
```

### 线 B · 新品市场调研（复用同一资产）

```
站点 + 词根 → 市场容量 → 竞争格局 → 长尾细分 →（需求方选方向）
  → 产品画像校验 → 对标竞品验证 → 利润与推广经济性 → 立项决策卡
```

**关键口径**：产品画像在 B 线里是**校验器**，不是起点——买家按词搜索，不按画像搜索。

### 模块边界（沿用 v0.1 的分工，新增一条）

| 插件 | 负责 |
|---|---|
| amazon-ops | CDP 浏览器采集引擎、ASIN 主档、Listing 文本、优化草案、发布登记、规则库（已验证，**复用不重写**） |
| sif-ops | 对象台账、SIF 四域时序、竞品集、对照报告、复测观测、新品调研链 |

桥接方式不变：sif-ops 只读 attach amazon-ops 的库拿已采内容；**sif-ops 不自己再造一个浏览器采集器**。

## 2. 对象模型（这是整个方案的地基）

```
产品族 Family            ← 一个「产品」，主 ASIN 是其代表
 ├─ 变体 Variant[]        ← 每个子 ASIN，带维度坐标（颜色/尺寸…）
 └─ 竞品集 CompetitorSet[] ← 每个族一份，状态机管理
```

### 2.1 族谱展开

- 输入任意子 ASIN → 从页面 twister 读 `parentAsin`（amazon-ops 已支持 legacy 与 inline 两种 twister）。
- 族内**变体坐标查重**：两个子体维度完全相同 → 记冲突、交人工，不自动合并。
- 一个子体挂到两个父体 → 记冲突，不自动选边。
- 无变体的单品 = 只有 1 个成员的族，走同一套流程。

### 2.2 竞品集（自动选 → 需求方确认）

候选三来源合并去重：

| 来源 | 工具 | 成本 |
|---|---|---|
| SIF 该词下份额 Top N | `market_get_keyword_competition` / `market_discover_competitors` | 2–3 点/词 |
| ABA Top3 点击 ASIN | `sif_keyword_aba.top3_asins`（已在库） | 0 |
| 亚马逊页面关联位（看了又看/买了又买/广告位） | CDP `related_competitors` 节（已有选择器） | 0 |

**过滤规则**（自动执行，结果入表）：
- 价格带偏离我 ±50% 以上 → 标「非直接竞争」，默认不选；
- 品牌词专属位 → 标「品牌型」，单独分组；
- 评分评论量级差 10 倍以上 → 标「跨档对标」，保留但不进中位数计算。

**状态机**：`candidate → confirmed / rejected`。需求方在页面上勾选确认；只有 `confirmed` 才进入对比计算。竞品集**带版本号**，每次确认生成一版，报告里写明用的是哪一版。

### 2.3 对比标尺（三档，不是两档）

每个指标都给三个数：**我 / 已确认竞品中位数 / 该词 Top3 标杆**。
只有「我 vs 我上个月」的报告，运营无法据此决策。

## 3. 采集方案（CDP 全字段）

### 3.1 字段覆盖矩阵

| 字段组 | 具体字段 | 采集方式 | 备注 |
|---|---|---|---|
| 基础 | 标题、品牌、价格、评分、评论数、BSR、类目、上架日 | CDP（amazon-ops 已有） | 复用 |
| 文案 | 五点、产品描述、后台 Search Terms | CDP 五点/描述已有；**Search Terms 页面不可见**，需人工补录 | 缺口① |
| 亮点 | Item Highlights（页面顶部短句） | CDP 新增选择器 | 部分类目无此区 |
| 变体 | 主 ASIN、全部子体、每子体维度坐标 | CDP twister（已有双布局支持） | 复用 |
| 主副图 | 全部图片 URL、是否白底、分辨率、顺序、有无视频 | CDP 图片区 + 图片 HEAD 请求取尺寸 | 已有 URL，尺寸需补 |
| A+ | A+ 模块类型、每模块文案、图片 | CDP `#aplus*`（已有区域） | 需细化模块级解析 |
| 品牌故事 | Brand Story 文案与图 | CDP 新增 | 与 A+ 同区不同模块 |
| 评论 | 评分分布、Top 评论正文、评论主题归纳 | CDP 评论摘要区（游客可见部分） | 见 3.3 |
| QA | 问答列表、回答数 | CDP 新增 | 游客态通常可见 |
| 属性 | 详情页全部属性键值（材质/尺寸/适配/包装等） | CDP（已有 4 个属性区选择器） | 复用 |
| 政策 | 该品类标题长度、必填属性、违禁词 | 规则库（人工维护，非采集） | 见 §6 |

### 3.2 采集调度

- 以 ASIN 为单位排队，每 ASIN 一页，逐页读取，**绝不并发**。
- 每页停留 ≥ 3 秒、滚动 2–3 次（图片懒加载与 A+ 需要滚动才渲染）。
- 每页落地两份东西：**结构化字段行** + **原始快照**（HTML 精简版 + 截图），供日后复查"当时页面长什么样"。
- 增量策略：价格/评分/BSR 每次必采；文案与图片先比哈希，没变就只记一行"未变化"。
- 验证码 / 登录墙：**立即停该批次**，记 `blocked`，交人工。不自动重试。

### 3.3 评论的诚实边界

游客态只能拿到：评分分布、少量 Top 评论、部分主题标签。**拿不到全量评论、评论者信息、时间序列全集**。
报告里评论模块必须标注"基于游客可见的 N 条评论，非全量"，不得写成"评论分析显示…"这种全称判断。

## 4. 分析与改稿

### 4.1 逐字段诊断（每字段一个判定）

| 字段 | 判定依据 |
|---|---|
| 标题 | 长度 vs 品类上限、核心词覆盖、词序、可读性、与竞品标题的词差异 |
| 五点 | 每条是否一卖点一证据、关键词分布、与竞品卖点的差集 |
| 亮点 | 是否回答了 QA 里的高频疑问 |
| 主副图 | 白底/像素合规（硬规则）、卖点图是否覆盖竞品有而我无的卖点（建议级） |
| A+ | 模块完整度、与五点的信息重复度 |
| 评论 | 差评主题 → 转化为五点/A+ 的答疑内容（不是刷评建议） |
| 结构 | 类目正确性、属性完整率 |
| 变体 | 维度覆盖缺口（竞品有而我无的颜色/尺寸）、变体间文案一致性 |
| GEO | 能否被 AI 直接引用：是否有明确规格、问答式句子、结构化参数 |
| 价格 | 所处价格带位置 vs 竞品分布 |
| 所有属性 | 与竞品属性表的差集（竞品填了我没填的） |

### 4.2 改稿原则（可直接上架的硬条件）

1. **每个改动的词必须有出处**：来自 SIF 词库（带当前排名与流量）或竞品文本差集，注明来源。
2. **不得编造规格**：尺寸/材质/适配等事实只能来自已采属性或需求方提供，缺了就标「待确认」，不猜。
3. **先过政策校验再进报告**：见 §6。
4. 图片/视频只出**脚本与分镜建议**（文字描述每张图拍什么、写什么卖点），不生成图片本体——这是诚实边界。

## 5. 对照报告（核心交付物）

### 5.1 主表结构（需求方指定格式）

| 列 | 内容 |
|---|---|
| 序号 | 字段序号 |
| 属性字段 | 标题 / 五点-1…5 / 亮点 / 描述 / Search Terms / 主图…副图-6 / A+ 模块 / 品牌故事 / 属性-×× / 变体结构 / 价格 / GEO |
| 原值 | 当前页面实际值（附采集时间） |
| 优化后的值 | 可直接上架的新值（图片字段为脚本建议） |
| 优化理由 | 详细：对标哪个竞品/哪组中位数、用哪个词（排名与流量）、解决什么差距、政策依据 |
| 历史版本 | 近两个版本可切换（v-1 / v-2 对照） |

### 5.2 三种视角（同一份数据，三种呈现）

| 视角 | 侧重 | 形式 |
|---|---|---|
| 自己 | 改什么、为什么、依据哪个词 | 完整对照表 + 证据链接 |
| 老板 | 差距多大、改完预期看什么指标、何时复测 | 摘要 + 关键差距图 + 复测计划 |
| 客户 | 分析过程、方法、透明度声明 | 完整对照表 + **透明度声明**（用了哪些工具、数据周期、样本范围、缺失字段、AI 结论边界） |

### 5.3 复测报告（闭环的最后一环）

改前基线 → 改后 7/14/30 天，逐节点对比：流量总分、自然/广告比、目标词自然位、评分评论变化、价格与 BSR。
每个节点给三选一结论：**有效（保持）/ 无效（回滚评估）/ 数据不足（继续观察）**，附证据。

## 6. 政策校验层（独立模块，报告前置闸门）

- 规则来源：**人工维护的规则库**（amazon-ops 已有规则表结构），不是从页面采集。
- 每条规则带：品类、字段、类型（长度上限/必填/违禁词/格式）、严重度（block/warn）、出处（政策文档名与日期）。
- **规则没有来源就不启用**——宁可漏检，不用没有出处的规则去卡文案。
- 报告生成前必跑：有 block 级违规的字段不允许标"可直接上架"，只能标"待修正"。
- 规则库带版本，报告记录"按规则库 vX 校验"。

---

## 7. 复测闭环（观测设计）

```
改稿确认 →（人工到后台发布）→ 发布登记（记录改了哪些字段、何时）
  → 自动建观测计划（7/14/30 天）
  → 到点提醒 → 重新采集 + SIF 同步 → 与基线对比 → 结论与建议
```

- **系统不自动上架**：发布永远由人在卖家后台做，系统只登记"已发布"这个事实及其时间。
- 观测基线 = 发布前最后一次完整采集的快照，冻结保存。
- 复测时若发现竞品集已变化（有新竞品进入），在报告中标注"环境已变"，避免把市场变化误判为改稿效果。

## 8. 数据模型（sif-ops 新增表，迁移链追加）

| 表 | 关键字段 | 说明 |
|---|---|---|
| `sif_family` | marketplace, family_id, parent_asin, created_at | 产品族 |
| `sif_family_member` | family_id, asin, dimensions_json, is_parent | 族成员与维度坐标 |
| `sif_competitor_set` | id, family_id, version, status, confirmed_by, confirmed_at | 竞品集（版本化） |
| `sif_competitor_set_member` | set_id, asin, source, tier, note | 成员（含来源与分档） |
| `sif_cdp_snapshot` | id, marketplace, asin, section, payload_json, raw_ref, captured_at, content_hash | CDP 全字段快照（按 section 分行） |
| `sif_optimize_round` | id, family_id, asin, competitor_set_id, status, created_at | 一轮优化 |
| `sif_field_change` | id, round_id, field_key, seq, before, after, reason, evidence_json, policy_verdict, version | **对照表主表** |
| `sif_publish_record` | id, round_id, published_fields_json, published_at, operator | 发布登记 |
| `sif_observation` | id, publish_id, node_day, metrics_json, verdict, created_at | 复测节点 |

原则：**改稿记录不可变**——每轮优化是新行，历史版本天然存在，不需要额外"版本表"。

## 9. 页面设计（在现有 8 个页签后新增）

现有：连接 / 对象 / 同步 / 看板 / 洞察 / 词库 / 竞品 / 优化

| 新页签 | 内容 |
|---|---|
| **产品族** | 输入 ASIN 列表 → 自动展开族谱与变体树；显示每族数据完整度 |
| **竞品集** | 自动候选列表（带来源与分档标签）→ 勾选确认 → 生成版本 |
| **采集** | CDP 任务队列、进度、每 ASIN 各 section 的采集状态（成功/缺失/被拦） |
| **对照报告** | 逐字段对照表（§5.1）、视角切换（自己/老板/客户）、近两个版本切换、导出 markdown/HTML |
| **复测** | 观测计划时间轴、每节点对比图、结论与回滚建议 |
| **新品调研** | B 线五阶段向导，每阶段独立确认后解锁下一阶段 |

「竞品」页签保留为词级竞争格局查看；「竞品集」页签管的是"拿谁来比"这份名单，两者职责不同。

## 10. 点数预算（每次优化一轮的估算）

| 项 | 工具 | 点数 |
|---|---|---|
| 我自己流量与词 | L1+L2（已有同步，多数情况走缓存） | 0–11 |
| 竞品格局 | `market_get_keyword_competition` × 2–3 个核心词 | 4–9 |
| 竞品产品画像 | `market_get_asin_profile` × 确认的竞品（≤8） | ≤16 |
| 需求与时机 | `market_get_keyword_demand` × 核心词 | 2–6 |
| **单族一轮合计** | | **约 10–40 点** |
| CDP 采集 | 浏览器，不走 MCP | **0 点** |

设计原则不变：**CDP 能拿的不花点，SIF 点数只花在 CDP 拿不到的市场与流量数据上**；已入库数据重复分析 0 点。

## 11. 分期与验收

### M1 · 对象与族谱
输入多 ASIN → 自动找主 ASIN、展开变体、族谱树展示。
验收：含变体的真实 ASIN 展开正确；变体坐标冲突能报出。

### M2 · 竞品集闭环
自动候选 → 页面确认 → 版本化入库。
验收：候选带来源；未确认不参与计算；确认生成版本号。

### M3 · CDP 全字段采集
按 §3.1 矩阵采齐，快照与结构化双落地。
验收：真实 ASIN 采回标题/五点/图片/A+/属性/QA/评论摘要；每字段有来源与时间；被拦时状态正确。

### M4 · 逐字段诊断 + 对照报告
三档标尺、逐字段差距、理由带证据。
验收：报告含需求方指定的 6 列；每条理由可回溯到数据；有透明度声明。

### M5 · 改稿 + 政策校验 + 版本切换
可直接上架的文案、政策闸门、近两个版本切换。
验收：违禁词/超长被拦；缺事实的字段标"待确认"而非编造；版本切换显示正确。

### M6 · 复测闭环
发布登记 → 观测计划 → 节点对比 → 结论。
验收：基线冻结；到点提醒；三选一结论带证据。

### M7 · 新品调研线
五阶段向导 + 立项决策卡。
验收：阶段门生效（未确认不能跳下阶段）；画像只作校验项出现。

## 12. 必须写进代码的硬约束（防翻车清单）

1. SIF 销量是**前台档位文本**（"5,000+"），不是精确值，禁止参与算术。
2. SIF 搜索量是**周**口径；CTR 是整体搜索点击率，不是 Top3 集中度。
3. 广告效果（花费/ACOS/CVR/订单）**SIF 没有**——只能做结构诊断；效果诊断需人工导入后台广告报表（列为后续可选模块）。
4. 评论分析必须标注样本量与"游客可见"边界。
5. 图片只出脚本建议，不生成图片；规格事实缺了就标"待确认"。
6. 系统不自动上架、不代填凭证、不绕验证码。
7. 政策规则无出处不启用；报告必带透明度声明。
8. 竞品集未确认不进入对比；族谱冲突不自动合并。

## 13. 已确认复用的现有资产（不重写清单）

- amazon-ops 的 CDP 浏览器引擎、Amazon 页面选择器（含双 twister 布局）、采集节（section）机制。
- sif-ops 的 MCP 客户端、迁移链、预算闸门、L1/L2 同步、词库、市场快照、Listing 诊断、报告生成骨架。
- 两者的侧边栏入口与 iframe 面板范式。

**新增工作集中在**：族谱与竞品集对象层、CDP 采集的字段扩展（亮点/QA/品牌故事/A+ 模块级）、对照报告与版本机制、复测观测、政策规则库内容、新品调研向导。
