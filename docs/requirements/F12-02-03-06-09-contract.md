### 2.7 又一处会被本批改旧的硬编码文案

`page.js` 的 `snapshotBlock`（约 `:4122`）逐字写着：

> **这四样是开始时拷贝的**：运行中升级规则或 Prompt 不改变它们。

「**四样**」是一个关于数量的断言。F12-03 加列后（配置版本、人工约束、输出格式），
这个数字会变大。**必须同改**，否则页面留一句假话 —— 与 §2.5 是同一类缺陷。

### 2.8 ⚠️ 一处**契约扩充**：`blocked` 的原因是**七条**，不是六条

需求 §6.2 逐字给了 blocked 的**六类**用途：数据过期、缺失必需变量、规则判定不可用、权限不足、
采集风控、成本超限。

`BLOCKED_KINDS` 有**七**条 —— 第七条 `interrupted`（运行中断）**不来自 §6.2**，
它来自 §12「任务中断：从最后持久化步骤恢复」，由 `recoverStaleAgentRuns` 写入。

**为什么并进同一列而不是另开一列**：「这条运行为什么走不动了」只能有**一个**答案。
开第二列就是本仓反复付代价的「同一件事的第二个名字」—— 页面得同时看两列才知道该说什么，
而两列总有办法不一致。所以第七条进 `agent_run.blocked_kind` 这**一个**封闭列。

**代价（如实记下）**：`agent_run.blocked_kind` 的取值集合因此**不等于** §6.2 的六类，
读到「六类」的旧文案会与代码不符。任何按「§6.2 的六类」写的断言/文案都要改。

## §3 本批**不做**什么（以及为什么）

| 不做 | 原因 |
|---|---|
| **成本 / token 的任何列或字段** | 没有这个来源。建一个永远 NULL 的列 = 把「没有来源」洗成「上限没设」 |
| **输入输出契约的字段** | 需求未给形状；插件侧无执行点。自造形状 = 把猜测写成规格 |
| **自动重跑中断的任务** | ⚠️ 需求说「从最后持久化步骤恢复」，但**恢复不等于自动重跑**：本插件不驱动 Agent（是会话在跑），插件自动「恢复」等于替会话决定继续执行。所以本批的 recover **只做一件事**：把僵死的 `running` 运行标成 `blocked` 并写明「中断于第 N 步，可从该步恢复」，**把决定权交回人/会话** |
| **配置的启停（enable/disable）** | §3 说配置视图含启停。但「停用」一个角色的**语义未定**（是不能再开新运行？还是现有运行也要停？）→ 本批只做版本与回滚，**启停留在登记里** |
| **删除角色配置的任何入口** | 版本表是追加式的；删除会破坏「已完成运行显示当时版本」 |
| 新工具超过 6 个 | 见 §4 数字 |
| 改 `src/domain/optimize/**`、`src/store/kw.js`、`src/sources/**` | 别的会话的区 |

## §6 已知边界（实现前就写明）

- **`promptModule` 是近似，不是精确绑定。** 视图里必须写清：它按 `prompt_set.module` 解析，
  一个模块下可能有几套集合，角色声明的是模块不是集合。谁要精确绑定，那是**另一次迁移**。
- **`outputFormat` 是约定，不是校验。** 插件没有产物格式校验器；写了 `outputFormat: 'json'`
  而产物是散文，插件**不会报错**。这条边界必须写在注释与页面上。
- **`onFailure` 是声明，不是自动执行。** 插件不驱动 Agent，所以它只影响**页面对失败步骤的建议措辞**
  与 `retryable` 的默认值 —— **不会自动跳步、自动降级或自动停止**。谁把它读成「插件会自动降级」，
  就是这个缺陷形状的新一次。
- **recover 只标状态，不自动重跑**（见 §3）。
- **成本仍然没有来源。** 本批之后仍是。

### 6.1 ⚠️ 「重试」的语义只能有一条路（实测状态机定的）

`src/domain/agent/run.js:25-34` 的 `RUN_EDGES` 里，`completed` / `failed` / `cancelled`
**都是终止态、没有任何出边**。所以：

| 情形 | 「重试」只能怎么做 |
|---|---|
| 运行在 **`blocked`** | **就地重试**：`blocked → running`（状态机**已经允许**）。§9 要求它显示为「**修复后重试**」 |
| 运行在 **`failed`**（终止态） | **新建一次运行**，用 `supersedes_run_id` 指向旧的。需求 §12 逐字：「上下文变化：**创建新运行，不修改旧运行**」 |

**不许**为了「重试一个 failed 运行」去改 `RUN_EDGES` 或重开终止态 —— 那会推翻 §6 的状态机
和 §15-6 的「中断后可从持久化步骤恢复，不重复已完成写入」。

### 6.2 ⚠️ 「修复完成前禁用」——插件**检测不到「修好了没有」**

§9 逐字要求：blocked 状态下「重试」改为「修复后重试」，**修复完成前禁用**。

插件**没有能力**判断一次补采 / 一次权限申请 / 一次范围缩小是否真的完成了。
所以诚实做法是：**按钮显示为「修复后重试」并保持禁用**，旁边写清为什么
（「本插件检测不到修复完成，所以不代你开跑」），并提供一条**显式的人工确认路径**
（确认时必须带一条理由，说明修了什么）—— **不是**假装检测到了、也不是自动放行。

**布局可以后续批次做（F12-06/09），但这条边界现在就要写进契约**，因为它决定了
「修复后重试」是**一个需要人工断言的按钮**，而不是一个「点一下就好」的按钮。

#### 9.4.1 ⑪ 抓到的那个 ReferenceError —— 本批最值的一条

`amzn_agent_run_finish` 的 `blockedKind` 拒绝**原本会掉进那个只带 `error` 的 catch**
（本文件四处 catch 都是 `{ok:false, error}` 的既有形状）。本批在碰库**之前**加了一次前置校验，
让它返回**三件套** `{ok:false, error, hint}` —— 判定仍走 domain 的**同一个** `blockedKindRefusal`，
不是第二份口径。

⚠️ **这是测试抓出来的，而且差一点没抓住**：⑪ 断言 `refused.code` 时发现它是 `undefined`，
而当时 `ok === false` **已经通过了**。根因是那次前置校验调用的 `blockedKindRefusal`
**根本没被 import**（`ReferenceError` 被 catch 吞成了 `{ok:false, error}`）。
也就是说：**一个只断言 `ok:false` 的测试，会绿着放过一个 ReferenceError。**
「拒绝必须是三件套」这条判据的全部价值就在这里。

### 9.6 已知边界（不许把「没测到」写成「没问题」）

- **`cost-exceeded` 写得出、判不出**：它在词表里（需求点名了），`blockedKindRefusal` **照收**它，
  但**没有任何路径能产生它**（本插件不调 LLM，`agent_run` 没有 token / 费用列）。
  页面**不画**它的出口按钮。**这不是「实现了一半」，是「这一类不可达」**。
- **`permission-denied` 的出口做不到**：§9 要「显示所需权限层级与申请路径」，而本插件**没有权限模型**
  （没有用户表、没有角色权限表，`agent_artifact.decide` 的 `by` 是自报标签）。画一个「所需层级：管理员」就是编的。
- **`rules-unusable` / `collection-risk` 没有出口**，因为**需求没给**。不许为了「整齐」硬套一个跳转。
- **`recover` 不恢复运行**：它只把「这条 running 很久没动了」写下来，把决定权交回人 / 会话。
  把它读成「插件会自动接着跑」是本批最容易犯的错（本插件不驱动 Agent）。
- **「修复后重试」永远点不动**：插件检测不到「修好了没有」（§6.2）。旁边那条「我已修复，继续」
  才是能走的路，且**必须带理由**。
- **`retryBudget` 的阈值只是判词**：本插件本来就不自动重试，所以 §12 的「多次失败停止自动重试」
  在本仓的真实含义是「**告诉人别再等它自己好了**」—— 它**不改变运行状态、不阻止任何写入**。
- **`supersedes_run_id` 不算上下文**：它是溯源指针，不在 `snapshotDiff` 的五维里。
- **取消保留全部产物**：本仓**没有**删除产物的路径；取消只动运行状态。
- **未跑真机**：本批没有浏览器验证环节 —— 页面的断言走的是真实渲染器与真实路由，
  但**不是**一个真的浏览器（§9.5 的 ⑨ 因此是**结构性**断言，见 9.7）。

### 9.7 ⚠️ 一处必须说清的断言强度（不许把它说强）
