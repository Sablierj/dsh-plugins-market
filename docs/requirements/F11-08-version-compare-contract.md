## §0 为什么是「只交材料」，而不是「跑九个维度的分」

需求文档 `RESEARCH-module-alignment-v2.0.md:307`（F11-08 行）**逐字**说：

> 事实一致/规则命中/关键词执行/结构完整/解释性/语气/稳定性/人工采纳率/成本
> 九维评分与 v2.3 vs v2.4 双版本对比**完全不存在**；没有固定输入快照，
> 也就没有「避免把数据变化误认为 Prompt 变好」的同一快照约束；
> **人工采纳率与成本两维在 `publication_record`/`observation_plan` 里也没有数据来源。**

**文档自己就点名了那两维没有来源** —— 这不是我的推断，是需求方的自述。

而「双版本对比评估」要成立，需要**两个版本的产出**。本插件：

- **不调 LLM**（全仓无任何模型调用通道）；
- `agent_run` **无 token / 费用列**（`src/domain/agent/gap.js:84-86` 已如实登记）；
- `prompt` 保存是**原地 UPDATE 覆盖**（`src/store/prompt.js:307-313`），**没有「版本行」**。

所以**两个版本都跑不出来**。能交的只有**材料**：两版正文并排 + 九维清单交给**人**来对照。

> **本仓铁律**：给缺失造一个像数据的替身，比留一个洞更危险。
> 九维**一格数字都不能填** —— 填了任何一个，就是这一批的全责缺陷。

## §1 九维的三种「没有」，必须分开说（本批的核心）

九维**逐字**（`RESEARCH:307`）：事实一致 / 规则命中 / 关键词执行 / 结构完整 / 解释性 / 语气 / 稳定性 / 人工采纳率 / 成本

它们**不是同一种缺失**，必须分成**三类**登记 —— 混成一句「都没有」本身就是
「把缺失折叠成有」的镜像错误：

> ⚠️ **契约自纠**：本节初版的标题与正文写「两种 / 分成两类」，而下面的表**本来就是三类**。
> 那是文案与内容不一致（本仓「文案比事实强」那一类缺陷）。已按表改正为**三类**。

| 类 | 维度 | 性质 | 该怎么写 |
|---|---|---|---|
| **A 有同名物，但不是本维** | ① 事实一致、② 规则命中 | 仓库里**有同名的东西**，但属于**别的模块/别的用途**，不能挪用 | 点名「同名物在哪、为什么不能当本维用」 |
| **B 概念未立项** | ③ 关键词执行、④ 结构完整、⑤ 解释性、⑥ 语气、⑦ 稳定性 | 全仓 grep **零命中**，既无表无列，也从未在 metrics/gap 里登记过 | 「需求已点名，代码侧从未立项」 |
| **C 无数据来源** | ⑧ 人工采纳率、⑨ 成本 | 概念存在且**算得出来类似的数**，但**对象不对 / 没有任何来源** | 「**没有这个来源**」，**不是 0** |

**A 类的具体证据**（这是最容易写错的一类 —— 看起来「有」）：

- ①**事实一致**：`src/domain/optimize/report.js:805` 有「事实一致 / 0 处冲突」，
  源自 `model.plan.factLedger.conflicts`。**但那是 listing 优化侧的闸门断言**，
  对象是 listing 草稿的产品事实，**不是提示词的输出**。不能挪用。
- ②**规则命中**：`prompt_eval_case.expect_rules_json`（`src/store/schema.js:2861`）
  语义是「必须至少命中的规则 id」。**但那是 F11-07 的样例声明**，
  是**人写的期望**，**没有任何「跑出来命中了几个」的记录**。
  更关键：**没有 LLM 就没有「命中」这个动作** —— 期望无法被兑现成事实。

**C 类的具体证据**：

- ⑧**人工采纳率**：全仓 `adoption` 唯一命中是
  `src/store/keyword-ownership.js:569` 的注释（语义无关）。
  最接近的是 `src/domain/agent/metrics.js:48,62,131` 的 `draft_adoption_rate`，
  它**算得出来**（`metrics.js:170-175`，口径 = `agent_artifact` 里
  `artifact-decision` 的 accepted/(accepted+rejected)）。
  ⚠️ **但它不是本维**：那个的对象是**模块 12 的 Agent 产物裁决**，
  本维的对象是**某条提示词的两个版本哪个被人选用**。**两者不可互换。**
  而且 F11-09 已实测证实：两个运行侧表都不记 prompt 引用
  （`src/domain/prompts/references.js:22-28`）—— 所以**没有来源**。
- ⑨**成本**：全仓**无任何 token/费用列**。最权威的登记在
  `src/domain/agent/gap.js:120-122`，原文逐字：
  > ⚠️ **没有这个来源**，不是「上限是 0」，也不是「上限没设」。

## §2 本批做什么

### 2.1 一个新常量文件：九维缺失登记

**新建 `src/domain/prompts/eval-dimensions.js`**，形状**直接对齐**
`src/domain/agent/gap.js` 的 `AGENT_GAP_ELEMENTS`（`:42-124`）与
`AGENT_GAP_SUMMARY`（`:135-137`）—— 这是本仓「如实登记缺失」的既有范式，
本批做的是**它的模块 11 版本**。

每条字段（与 `gap.js` 同名同义，降低读者切换成本）：

| 字段 | 含义 |
|---|---|
| `id` | 稳定 id（如 `fact-consistency`），**不随 label 变** |
| `label` | 中文维度名，**逐字取自 `RESEARCH:307`** |
| `kind` | `'same-name-elsewhere'` / `'concept-not-started'` / `'no-source'` —— **§1 的 A/B/C 三类** |
| `sameNameAt` | 仅 A 类有：同名物的 `file:line` + 一句「为什么不能挪用」 |
| `missing` | 「缺哪份记录」。**C 类必须逐字含「没有这个来源」；B 类必须含「从未立项」** |
| `source` | 有来源就写 `file:line`；本批**九维全无来源**，故逐条写清缺什么 |

**外加两个派生量**（对齐 `gap.js` 的 `AGENT_GAP_COUNT` / `AGENT_GAP_SUMMARY`）：

- `EVAL_DIMENSION_COUNT` = 9（并**断言它确实等于九**，见 §4）；
- `EVAL_DIMENSION_SUMMARY` = 一句话结论，必须同时说清 §1 的**两类**缺失。

⚠️ **不写任何数字**。这个文件里**不该出现 `0`**（除数组下标语义外）。
写测试钉住这一点，见 §5 证伪②。

### 2.2 页面：并排两版正文 + 九维清单（**纯只读，无 button**）

在**已有的**提示词评估区旁加一块「双版本对比（材料，不含评分）」：

- **左/右并排**两个版本的正文 —— 取法见 2.3；
- **下方**渲染九维清单表格，表头逐字对齐 `metricsBlock` 的既有措辞
  （`page.js:4222-4254`，表头「缺哪份记录（不是「未实现」）」）；
- **服务端不下发时**必须画一句「服务端没有下发这一格 —— 与『九维都没有缺失』不是一件事」，
  对齐 `gapsBlock` 的 `page.js:4258-4274` 既有写法。

⚠️ **本批页面不加任何 `<button>`**：没有可执行的动作 —— 没有评估器可跑，
没有结果可存。「一个点了无事发生的按钮，比没有按钮更糟」。

### 2.3 两版正文怎么取（**不许发明正文**）

- **`promptHistory(store, { id, includeArchived, limit })`**（`src/store/prompt.js:982`）
  返回 `rows[].body` + `rows[].version`（`:1005` 起）。这是**同一提示词历史版本的权威取法**。
- ⚠️ **冻结数 ≠ 版本数**：`src/store/prompt.js:965-968` 原文
  「creating a row freezes nothing, so `frozen = version − 1`」，
  且 B-11.2b 之前的行可能**更少**。
- ⚠️ **pointer 快照的 `body` 是 `null`**（`:1005` 注释明确「不发明正文」）。
  → 必须**分开渲染**「这一版没有冻结正文」，**不能画空白格**，
  也不能用 `?? ''` 把「没有」折成「空」。**这是本批第二个承重点。**

### 2.4 输入快照：**本数据模型里没有这条关联**（契约自纠）

> ⚠️ **本节初版是错的，这里是裁定后的版本。** 初版写「在对比材料里**列出该提示词关联的
> 评估样例输入**」—— 该前提**不成立**：数据模型里**没有「提示词 ↔ 评估集」这条关联**。
> 这是独立对抗验收者在 `c45dffb` 上判定的 BROKEN-1，主理人复核后裁定**撤掉该特性**，
> 不是修成「能用」。

**证据（三条，各自独立成立，均已实测）**：

1. **两个 id 空间不相交。** `prompt.set_id` 的外键是
   `REFERENCES prompt_set(id)`（`src/store/schema.js` 的 `CREATE TABLE prompt`），
   而样例挂在 `prompt_eval_set` 上（`getEvalSet` 查 `SELECT * FROM prompt_eval_set`）。
   实测：把**真实评估集** `keyword-listing-v1` 导进库后，`prompt_set` 的 13 个 id 全是 UUID、
   `prompt_eval_set` 只有一个 `keyword-listing-v1`，**交集为空**。
2. **没有任何列能承载这条关联。** `PRAGMA table_info` 实测：
   `prompt_eval_set` 的列 = `["id","version","title","category","note","created_at"]`、
   `prompt_eval_case` 的列 = `["id","set_id","set_version","case_index","category",`
   `"input_json","expected","expect_rules_json","created_at"]` ——
   **两者都没有指向 `prompt` / `prompt_set` 的列。**
3. **version 类型也对不上。** `prompt.version` 是 `INTEGER`（编辑计数器），
   `prompt_eval_set.version` 是 `TEXT`；`getEvalSet` 会 `String(version).trim()` 去比 TEXT 列。

**所以这一半属于 §1 的 C 类 `no-source`：没有这个来源。**
不是「查不到」，不是「为 0」，也不是「关联了但是空」。

**本批的做法**：路由下发 `compare.evalInputs = { available: false, reason: 'no-prompt-eval-link' }`
——一份**如实登记**；页面对它画的是「这条关联**没有建立**……**没有这个来源**」，
并**明说**「不是『样例为空』、也不是『查错了集合』」。

⚠️ **不许**写成 `[]` 或 `null`：数组（哪怕是空数组）都预设了「关联存在、只是没样例」——
那是把一处**不存在的来源**渲染成一处**空来源**。断言 ⑦-1 钉住这一点。

⚠️ **不许**在页面上出现「关联了评估集」「集合为空」「该集合里还没有样例」这三句话 ——
它们都预设了「关联」这个概念存在。断言 ⑦-2 钉住这一点。

⚠️ 将来真要这条关联，是**另一次迁移**（新增关联表），不是在这里补一行查询。

### 2.5 路由：只加下发字段

`routes.js` 的 `promptEditor` 下发里加 `compareDimensions` 与对比材料，
对齐 `routes.js:3129-3133` 现有的 `evalSets` 下发方式。

## §3 本批**不做**什么（以及为什么）

| 不做 | 原因 |
|---|---|
| **九维的任何分数 / 通过率 / 排名** | 没有任何一维有来源。填一个数就是本仓最贵的缺陷 |
| **「哪个版本更好」的自动判定** | 需要 LLM 判读，且需要人写口径。**判定必须由人做** |
| **结果表** | `schema.js:2820-2824` 逐字：「本批不跑评估…**没有结果表**…把期望与结果混在一张表里，会让『还没跑过』读成『跑过了』」。这条同样适用于 F11-08 |
| 新迁移 / 新表 / 新列 | 对比材料 = 两版正文 + 静态九维清单，**无新事实需要落库** |
| 新工具 | 读正文用现成 `amzn_prompt_history`；读样例用现成 `amzn_prompt_eval_show`；九维是**代码常量** |
| 新写路由 | 本批无写动作 |
| 自造九维口径 | 文档**只给了名字、未给口径**。自造口径 = 把猜测写成规格。**「口径未给」本身要作为一条缺口如实登记** |
| 把模块 12 的 `draft_adoption_rate` 当成本维的人工采纳率 | 对象不同（Agent 产物裁决 ≠ 提示词版本选择）。见 §1 |

| 项 | 约定 |
|---|---|

## §5 验收

1. **全量绿**，报实测 passed/failed/EXIT。
2. **断言只增不减**：给出前后断言数。
3. **至少两次真证伪**（回退 → 变红 → 改回），**逐字贴断言名与期望/实际**：
   - **证伪①**：把九维常量删成 8 条 → 必须红（钉住「恰好九」）。
   - **证伪②**：在 `missing` 里塞一个数字（如把「没有这个来源」改成「0」）→ 必须红
     （钉住「一格数字都不能填」）。**这是本批的承重断言。**
     ⚠️ **裁定后加严**：只验一种填法不够。独立验证者实测初版的黑名单口径
     **16 种现实填法漏 12 种**（`命中 2 条规则` / `0.5` / `值:0` / 全角「：」…全漏）。
     现改为**白名单口径**（剥掉「特性号 / 模块编号 / file:line 引用」这三类**编号与坐标**
     后，断言无阿拉伯数字），并要求**逐种**给出证伪输出。
4. **「没有来源」与「值为 0」分开说**：报告里必须逐维标明属于 §1 的 A/B/C 哪一类。
5. 交接条写进 `docs/COORDINATION.md`，含**四要素** + 逐条**证据等级**
   （`verified`/`documented`/`unverified`/`stale`）。**不许把「没测到」写成「没问题」。**

## §6 已知边界（实现前就写明）

- 本批**不减少任何未知**：九维仍然九维全缺。差别是它们从**文档**走进了
  **可查询、可渲染、可与代码对账**的结构化记录。
- **「口径未给」是第二条缺口**，与「无来源」并列。本批如实登记两条，不合并成一条。
- **人工采纳率在别的模块有类似物**（`draft_adoption_rate`）。本批**不接线**它 ——
  对象不同。若将来有人要接，那是一个**新的裁定**（要不要把 Agent 产物裁决
  当作提示词采纳率的代理价值），**不是本批能自行决定的**。
- **§2.4 的样例输入特性已撤**（见 §2.4 的「契约自纠」）：数据模型里没有那条关联。
  页面上那一块现在只说「**没有这个来源**」。想让它变成真的，需要**另一次迁移**。
- **断言 ⑤ 的射程边界**：只查**阿拉伯数字**，不查中文数字（「命中两条」不会被抓）。
  理由：中文数字在本仓是正常行文的一部分（「两个 id 空间不相交」「三类缺失」），
  一律拦会让 ⑤ 变成**永远红的断言** —— 而永远红的断言与永远绿的断言是同一类缺陷。
  这条边界是**声明的**，不是漏掉的。
- 页面那块**只在新装库上显示「样例为空」的**只有 F11-07 的评估集清单；
  F11-07 的迁移不播种数据，所以「库里 0 套评估集」是**正常态**，不是缺陷。
