## §2 逐项裁定

### A. 任务类型：**加，但可选**，且「未声明」必须看得见

**做什么**

1. **`src/domain/agent/roles.js`** 新增封闭词表，放在 `AGENT_STEP_STATUSES`（`:65`）旁边 ——
   与模块 12 其它词表同处（`states.js` 是**跨模块**词汇表的家，它连一个 import 都没有；
   模块 12 自己的词表一直住在这里）：

   ```js
   /* §5 六类任务类型。**词表与中文标签各只有一份** —— 页面照它画，不自己写第二份。 */
   export const AGENT_TASK_TYPES = ['qa', 'analysis', 'generation', 'validation', 'flow', 'maintenance']
   export const AGENT_TASK_TYPE_LABELS = {
     qa: '单步问答', analysis: '分析', generation: '生成',
     validation: '校验', flow: '流程', maintenance: '维护',
   }
   ```

2. **迁移 v43**（`src/store/schema.js`，追加在 `MIGRATIONS` 数组**末尾**，
   `name: 'agent-run-task-type'`）：

   ```sql
   -- ── F12-04 缺半：§5 的六类任务类型 ─────────────────────────────────────────
   -- ⚠️ 可空、**无默认值**。老运行就是「未声明」——给它一个默认类型等于
   -- 给缺失造一个像数据的替身（本仓铁律里最贵的那条）。迁移**不播种**。
   ALTER TABLE agent_run ADD COLUMN task_type TEXT;
   ```

3. **`src/store/agent.js` 的 `startRun`**（`:268-271`）加 `taskType = null`，**先校验再碰库**
   （与 `humanConstraint` / `outputFormat` 同一条纪律，`:276-279`）：给了值就必须在
   `AGENT_TASK_TYPES` 里，否则抛 `` `unknown task type: ${值}` ``。`null` 写 NULL。
   插入语句的列清单与占位符**同步加一列**（`:290-305`）。
   读侧 `getRun`（`:137+`）与 `listRuns`（`:204+`）的映射各加 `taskType: row.task_type`。

4. **`src/tools/agent.js` 的 `amzn_agent_run_start`**：`parameters.properties` 加 `type`
   （**不进 `required`**，`:147` 保持 `required: ['role']`），描述里写明
   「六类之一；**不传表示未声明**，不要为了填满而猜一个」。
   返回文本里回显一行：`任务类型: 分析` 或 `任务类型: 未声明（这次运行没有声明类型）`。

5. **`src/web/routes.js`**：agent 切片（`:3682` / `:3792`）下发 `taskType` ——
   **下发原始值，不要在下发时折算成默认类型**（折算会让页面永远画不出「未声明」）。

6. **`src/web/page.js`**：运行列表行 + 运行头各显示一处，**未声明时逐字画「未声明」**，
   且那一格**不得**等于任何中文标签。

**为什么不设默认值、也不设 required**（本批最要紧的一条，**请勿改**）

- §17.3 的 v1.1 最小集**没有**任务类型；今天 8 个测试文件 + 会话侧的调用方都并不知道自己属于哪一类。
- 给默认值（例如 `'analysis'`）= **给缺失造一个像数据的替身** —— 本仓铁律里最贵的那条。
- 设成 `required` 会**逼调用方在不知道时随便挑一个** —— 同样是在制造假值。
- 所以：**可选 + 缺省 NULL + 页面与工具都必须把「未声明」画成「未声明」**，
  与 v41 那批「新列一律可空、无默认值」（`schema.js:2950`）的理由完全一致。
- 由此：**六类 + 「未声明」是七个状态，不是六个。**

### B. `mode`：**让它说实话**（而不是删掉它）

**做什么**

1. **`src/domain/agent/orchestration.js`**：`:154` 改为**从已算出的 `reviewCount` 派生**：

   ```js
   /* §7.1 顺序 vs §7.3 审阅循环。判据是**已经发生过什么**，不是角色声明了什么：
      reviewCount > 0 意味着至少有一条步骤被重复记录过 —— 那就是审阅循环转过了。
      这两个值是**实际存在的两种模式**；§7.2 并行与 §7.4 条件分支没有实现，
      所以它们**不进词表**（什么时候真做了什么时候加）。 */
   const mode = reviewCount > 0 ? 'review-loop' : 'sequential'
   ```

   ⚠️ `reviewCount` 必须**先算**（`:149-152` 已经在 `mode` 之前 —— **别挪顺序**）。

2. **同时导出标签表**（页面与工具都照它画，**不写第二份**）：

   ```js
   export const AGENT_PLAN_MODE_LABELS = { sequential: '顺序', 'review-loop': '审阅循环' }
   ```

3. **给它读者**（否则它仍然是孤儿）：

   - `src/tools/agent.js` 的 `contractTail`（`:506-513`）：`plan.mode === 'review-loop'` 时补一句
     `\n编排模式：审阅循环（同一步骤已被重复 ${plan.reviewCount} 次）`；
     `'sequential'` 时**不加噪声**（顺序是常态，不需要每次都说）。
     ⚠️ 数字取 `plan.reviewCount`，**不要在工具里重算**（单源）。
   - `src/web/page.js` 的 `nextStepBlock`（`:4797-4820`）：在判词之后补一格
     「编排模式：顺序 / 审阅循环」。⚠️ **只增不改** —— 既有那几支判词的文案一个字都别动。

4. **加断言**（`tests/f1205-orchestration.mjs`，新开一节）：至少四条 ——

   - 没有重复步骤 → `mode === 'sequential'`；
   - 同一步骤被记录两次且**未超限** → `mode === 'review-loop'`；
   - 达到上限（`verdict === 'review-exhausted'`）→ `mode === 'review-loop'`；
   - **可证伪**：断言两个值**都真的出现过**（在同一个测试里收集到一个 Set 再比大小），
     否则就是「永远绿的断言」——本仓对这类断言有明账（见 `MEMORY.md` 坑 13）。

   ⚠️ **断言只增不减**：该文件里任何既有断言**一个字都不许改**。

## §3 不做什么（明确列出，**不是遗漏**）

1. **不做 §7.2 并行、§7.4 条件分支。** 理由是**数据现实**：并行要求「分字段并行生成 + 合并检查
   （关键词重复 / 事实一致 / 全局容量）」，插件没有分字段生成器；条件分支要求「评分 < 3.8」
   这类阈值输入，插件**没有评分来源**（没有 LLM 通道）。**给它们造一个模式名字而不实现行为
   = 把缺失渲染成能力** —— 那正是本仓最贵的那类缺陷。维持 B-12.5 已登记的裁定。
2. **不把 `mode` 扩成四种模式的名字。** 词表只放**实际存在的两种**。
3. **不给 `agent_run.task_type` 回填历史行。** 迁移不播种（结构 vs 内容）—— 老运行就是「未声明」。
4. **不动 `AGENT_ROLES` 的 `available` 标记、不动门禁、不动 F12-06 / F12-09 的任何行为。**
5. **不新增工具**（见 §1.3）。
6. **不碰 `src/web/page.js` 里模块 12 之外的任何区块**（反引号预算共用，见 §5.7）。

## §5 测试必须钉住的（少一条都不算完成）

1. **迁移**：`SCHEMA_VERSION === 43`；`PRAGMA table_info(agent_run)` 里有 `task_type`；
   **v42 的库升上来后老行 `task_type IS NULL`**（不是某个默认类型）。
   ⚠️ 断言「**版本号大于 42 的都跑了**」，**不要**钉「恰好等于 43」（本仓为钉绝对数字付过多次代价）。
2. **词表与标签一致**：`AGENT_TASK_TYPES.length === 6`；`AGENT_TASK_TYPE_LABELS` 的键集合与
   `AGENT_TASK_TYPES` 的**对称差为空**（用对称差断言，**不要**用数量相等 —— 数量相等 ≠ 集合相等）。
3. **拒绝**：`startRun(..., { taskType: 'made-up' })` 抛错，且**没写库**（写前后 `COUNT(*)` 相等）；
   `amzn_agent_run_start` 传非法 `type` 时返回 `{ok:false, error, hint}`（三件都要 ——
   只回中文句子的拒绝会被审计漏斗与遥测**同时**判成成功）。
4. **「未声明」与「某一类」必须可区分**：不传 `type` 的运行，页面渲染出的那一格是「未声明」，
   且**不等于任何一个中文标签**。
5. **mode 可证伪**：两个值都真的出现过（§2.B.4）。
6. **审计**：本批**没有新写路径**（`agent_run` 的写已有 `WRITE_TARGETS` 描述符），但 `task_type`
   是新列 → 用 **A/B 对照**确认 `amzn_agent_run_start` 仍然落审计行（开一次运行 → 审计 +1）。
7. **页面**：`node scripts/check-page.mjs` 必须 **3/3**；`page.js` 反引号预算
   `grep -o '\`' src/web/page.js | wc -l` **改前量一次、改后量一次并报告两个数**
   （模板字面量里**注释里的反引号**会提前闭合文档，是唯一会静默炸的合并风险）。
