### 0.2 ⚠️ 订正我**自己**在 B-12.6 里的一条 over-claim

B-12.6 的 §3.37 写着 `contractTail` 的静默「同时覆盖「顺序 / `plan === null` / `expected.length === 0`」
三种情形，读者分不出」。**这句话在函数契约层成立，在运行时是错的。** 实测（`src/tools/agent.js:380-397`）：

- `plan === null` 需要 `before === null`；但**紧接着**的 `setRunStatus`（`src/store/agent.js:356-360`）
  对同一个 run **先抛** `no agent run <id>` → 落到 `catch` → `contractTail(plan)` **根本不被求值**。
  ⇒ **该分支是可证死代码。**
- `expected.length === 0` 需要 `roleById(run.role)?.steps` 为空 —— **三条路径可达**
  （这一条是我写契约时的**第二处错**，独立验收者用原始输出推翻了「只有孤儿角色」那版）：
  ① 运行的 `role` 不在 `AGENT_ROLES` 里（旧版本写的库行 / 直接插库的行）；
  ② **配置发布路径** —— `amzn_agent_role_config_release` 可以把一个**代码 `steps` 为空、但在表里**
     的角色（如 `collect-coordinator`）发布成 `available: true`：`validateRoleConfig`
     （`roles.js:383-405`）明确允许 `steps: []`（它自己的 hint 逐字写着「空数组是允许的」），
     而 `startRun` 只查 `config.available !== true` 于是**放行** ⇒ 这一支被触发，
     **而角色就在角色表里**；
  ③ 三个可用角色的代码 `steps` 都非空（`roles.js:147/171/192`），所以「可用且代码有步骤」走不到这里。

  ⇒ **推论（本批因此改了实现）**：`expected.length === 0` 那句话**不许断言原因**。
  写成「该角色不在角色表里」会在路径 ② 上变成**假话** —— 假说法正是本批在消灭的东西，
  不能由本批再引入一次。P5 的结构性不变量只钉住**代码声明**，钉不到**已发布的配置**。
  （路径 ② 有专门断言：`tests/b12-10-closeout.mjs` 的 D1 ⑥。）

**所以「三态不可区分」不是运行时的真实歧义。** 本批的诚实收口是「显式化 + 加不变量」，
**不是**「补齐三态」—— 后者会把一个不存在的缺陷渲染成已修。

## 1. 交付 D1 · `contractTail` 的静默与死守卫

**落点**：`src/tools/agent.js` 的 `contractTail`（现 `:523-537`），唯一调用点 `:396`。

**现状**（原文）：
```js
function contractTail(plan) {
  if (plan === null) return ''
  if (plan.expected.length === 0) return ''
  ...
}
```

**要求（性质，不是实现）**：

- **P1** `contractTail` **不得**用 `return ''` 表示「关于契约无话可说」。沉默与「顺序」不可区分
  （本仓最贵的形状）。**唯一例外**：`verdict === 'done'` / 未走完 这两条正常路径已经各吐一句，
  它们不是沉默。
- **P2** `plan === null` 分支**可证死**（见 §0.2）→ **删掉**，并在函数注释里写明**为什么到不了**
  （写清楚：`setRunStatus` 先抛）。**不许**留一个「看起来在处理第三种输入」的空壳。
- **P3** `expected.length === 0` 分支**可达**（孤儿角色）→ 改成**说出来**的一句，
  例如「⚠️ 这次运行的角色的步骤契约是空的（该角色不在角色表里），无法核对契约是否走完」。
  **不许**继续 `return ''`。
- **P4** **不得**让 `sequential` 也输出「编排模式」句。`tests/b12-9-task-type.mjs:481-485` 的
  对照臂（「顺序也报了模式，那是噪声」）是**证伪控制**，不是缺陷 —— 它证明「有重复就报模式」
  不是「无论如何都报」。**该断言一个字都不许改。**
- **P5** 新增一条**结构性不变量**断言：**每个 `available: true` 的角色必须声明非空 `steps`**。
  理由：它是 P3 那条分支的「不可能」的唯一依据；一旦有人把无步骤的角色标成可用，应当是
  **测试变红**，而不是输出变哑。

**新增断言（可证伪）**：
1. 直接插一行 `role` 不在 `AGENT_ROLES` 里的 `agent_run`，再调 `amzn_agent_run_finish` →
   输出**必须**含那句「契约是空的」；**回退 P3 → 变红**（贴原文）。
2. `AGENT_ROLES.filter(r => r.available === true).every(r => r.steps.length > 0)` —— 不变量。
3. 回归：`tests/b12-9-task-type.mjs` 的七节全绿且**未被改动**（用 `git diff --stat` 证明该文件零改动）。

**不做**：不新增工具、不新增导出、不动 schema。

## 4. 交付 D4 · F12-10 的「页面→会话」半边（**不许造假深链**）

**审计原话**（仍成立）：「『互跳』只做了会话→页面一半……**页面→会话没有任何链接或复制入口**。」

**实测（否定结果，但措辞必须校准）**：**本插件页没有通到会话的桥，插件也没有面向那条通道的 API** ——
所以**做不了真跳转**：
- 唯一深链是 `dsh://open`，注册在 `deploy/apps/desktop/src/main.ts:1228`，**只精确匹配**
  `url === 'dsh://open' || 'dsh://open/'` → `focusPrimaryWindow()`。**不解析载荷、不注入会话。**
- 插件页是**系统浏览器标签页**（`scripts/open-web.ps1` 取授权 URL 后 `Start-Process`），
  页内无 `postMessage` / `window.parent` 桥（`grep src/web/` 为空）。

⚠️ **契约初版在这里写错了（过绝对）**，独立验收者用代码级证据驳回：**不能写成「本 harness 里没有
页面→会话的载荷通道」**。harness 自己有一条 —— `packages/api/session-controller/src/index.ts:425`
的 `@Remote('prompt')`（把 prompt 送进 session），经 `packages/api/gateway/src/index.ts:252` 的
`/api/remote.mux` 暴露；准入门是 `isTrustedApiRequest` + `browserAuth.isAuthenticated`，其 cookie
为 `Path=/; SameSite=Strict`（**同源自动携带**），而插件页与 mux **注册在同一个 `webServer` 上**
（`src/web/routes.js:450/466`）⇒ **同源**。
**正确的说法是**：「插件页没有桥、插件也没有面向这条通道的 API；harness 那条通道**未端到端验证
可用**（需真 harness + 真 session id + 复刻 mux 的 Typert 流协议），且插件当前只声明
`inject=['tools']`。」把「我没接」写成「世上没有」正是本批在消灭的假说法。

⇒ **任何「点一下就回到会话」的链接都是假的。本批只做「复制一段话去问 agent」，不造假深链。**

**本仓既定的「回传」先例**（唯一）：`usePrompt(value)`（`page.js:2778-2781`）——
往 `promptBox` 塞一段 prompt 并复制到剪贴板，由**人**粘贴进对话。紧邻注释（`page.js:2775-2777`）
逐字写着本仓的规矩：`a page button has exactly two outcomes, a POST of one fact or a prompt —
never a direct tool call.`

**要求**：
- 在 `renderAgent` 的运行详情里加**一个**按钮，复用 `usePrompt(...)`，文本形如
  「这次运行 id 是 `<id>`，用 `amzn_agent_run_list` 可以取回它」。
- **文案不得暗示「跳转」/「回到会话」** —— 它是「复制这段去问 agent」。
- **不做**产物的 `objectType`/`objectId` 可点：实测**多数 `object_type` 没有对应页面落点**
  （可点的只有 `MODULE_GROUPS` 里那些模块锚点，且要该模块接受相应 filter 键）。按 `objectType`
  猜锚点就是猜（`page.js:6286-6288` 已有同款明账）。**保持纯文本，并在页面上明说没有落点。**

**新增断言（可证伪）**：① 按钮存在且文本含 run id；② 断言渲染产物里**不出现** `dsh://`（证明没造假链接）。
