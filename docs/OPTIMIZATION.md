# memory-bridge 设计与优化方案

> 面向「一个 DSH 用户能不能靠这个插件把 TDAI 记忆用起来」这条主线写的评估。
> 版本基线：0.7.0；测试入口：`npm test`（39 项，全绿才允许发布）。

## 一、现状（能力边界先说清）

| 层 | 实现 | 边界 |
|---|---|---|
| 传输 | 面板 `/relay/<id>` + `X-Relay-Key`，直连 `127.0.0.1:8420` 也可 | 依赖面板存活；面板挂了记忆全断 |
| 方言 | 自动识别 v3（部署版）/ v1（开源版），5 分钟 TTL | 只覆盖已探测的两套路由；新版接口需手工加白 |
| 召回 | `agent/pre-step` → L1 检索 → 注入系统提示词 | 只查 L1；L2/L3 靠模型主动 `memory_browse` |
| 写回 | `agent/turn-stopping` → L0 追加 | 只写原始对话，L1 提炼靠网关 |
| 观测 | 三段状态（网关/代理/隧道）+ 本地日志 | 日志是本地的，跨机器要人工导 |
| 面板 | 概览 / 浏览 / 设置 + 30s 自动刷新 | 可见性靠 CSS token，宿主改版需回归 |

**一句话**：读写链路已经闭环，剩下的是「稳、省、快」三个字的工程问题。

## 二、问题清单

### P0（会影响用户，已在本轮修完）

1. **自动捕获静默失效** —— `agent/turn-stopping` 是 **serial** 事件，处理器必须返回 Promise；原来写 `void flush(...)` 导致事件链不等待、捕获常常丢。改为 `async () => { await flush(...) }`。
   *回归测试*：`[3] 自动捕获` 三项（监听器注册 / 真的写 L0 / 含用户原话）。
2. **开关要重启才生效** —— 监听器原先注册在 `if (current.autoCapture === true) { ... }` 里，`apply()` 时就定型了；面板上打开「一键配置」只改了配置文件，**监听器根本没注册**，必须重启宿主才生效（用户看到的就是"点了没反应"）。
   现在改成**常驻注册 + 触发时读 `current`**：`flush()` 里先判 `current.autoCapture !== true` 直接返回，召回同理。
   *回归测试*：`[4] 运行时开关` 两项（停用后不写 / 重新启用立刻恢复，无需重启）。
3. **`agent/turn-stopping` 在部分会话里从不触发** —— 目标循环 / 长工具链的会话走不到「即将关闭」那个点。补了必然发生的 `agent/status === 'idle'` 作为第二触发点。
   *回归测试*：用例覆盖 idle 触发。
4. **`agent/pre-step` 的 `messages` 多数 step 是空的** —— 它触发在**每个 step** 前，只有「有新消息」的那个 step 才带 messages。拿它当用户文本的唯一来源，等于把这一轮的话丢掉（自检显示 `injectShape={count:0}`、`lastUserChars=0`）。
   正确钩子是 **`agent/inbox/claimed`**（用户消息离开收件箱，`payload.message` 就是这一刻的用户原话）。pre-step 保留为兜底。
   *回归测试*：`[6] 收件箱钩子`。
5. **面板不能滚、配色反向、CSS 变量名编造** —— 已在 0.4.x 修（app-shell 滚动容器、`--dsw-alias-*` 真 token、`color-mix` 派生半透明色）。

### P1（下一版值得做）

3. **召回质量不可观测** —— 现在只知道"召回了 N 条"，不知道"有没有用"。建议在 `agent/pre-step` 记 `query → 命中 id 列表 → 注入字符数`，面板加一列"命中率/空召回率"。空召回超过 40% 说明知识库该补了。
4. **写入没有去重** —— 同一条对话重复触发（重试、fork）会写两遍 L0。建议以 `sessionKey + turn + 内容哈希` 做幂等键，网关侧或本地都行。
5. **面板缺少"写入"入口** —— 只能靠对话自动写。建议概览页加「记住这条」：手输一句话 → `memory_save`，让用户能主动纠正记忆。
6. **代理开关依赖面板 api_key** —— 没配就只能看不能改。建议探测 MemoryProxy 自身是否有管理口（本轮 `GET /`、`/admin/*` 均 404，暂无），没有就保持现状并在 UI 上标灰说明。

### P2（体验/工程）

7. 日志只落本地，多机部署难排查 → 建议支持"复制诊断包"（配置脱敏 + 最近 50 条日志 + 三段状态 JSON 一起复制到剪贴板）。
8. 自动刷新固定 30s → 建议做成可配置（10/30/60/关闭），并区分"前台标签页"与"后台静默"两档。
9. 场景详情是纯文本 → 建议按 markdown 渲染（标题/列表/代码块），现在 `Prose` 已做最小解析，可再补链接与表格。

## 四、验收标准（下一版沿用）

1. `node test/run-tests.mjs` 全绿，新增能力必须有对应用例。
2. 面板改动必须在 400px / 800px 两个宽度下截图确认不重叠、可滚动。
3. 颜色只用 `--dsw-alias-*`，不出现字面色值（`grep '#[0-9a-fA-F]{6}' client.js` 只允许注释命中）。
4. 任何新配置项必须有默认值 + 在 `publicConfig` 里以 mask 形式暴露，密钥永不回传明文。

## 五、端到端验收记录（2026-11-04，真实环境）

链路跑通的证据链（不是 mock）：

1. 插件自检：`registered={preStep:1,turnStopping:1,assistantStream:1,statusIdle:1,inboxClaimed:1}`、`lastUserChars=625`
2. 写入：`writes=1`，日志 `capture ok · count=1 · chars=400`（400 = MAX_QUERY_CHARS 截断）
3. 网关接受并提炼：L1 原子数 **1 → 2**
4. 召回验证：`memory_recall("记忆服务插件 迭代优化 一键设置")` 返回了这一轮被提炼出的原子

至此「说一句话 → 自动写回 → 网关提炼 → 下次自动想起」整条链路闭合。

**已知边界**：网关的 `/v3/conversation/search`（L0 检索）对刚落库的对话有延迟或相关性阈值，刚写完立刻搜可能 0 命中；L1 侧正常。这不是插件问题，是网关索引行为。
