# 拓展角色与运营方案（v0.2 增补）

> 04 文档给了四个基础角色（运营 / 数据分析 / 关键词研究 / 市场分析）。这一份是**把岗位拆细**：
> 6 个可独立交付的角色 + 10 套能直接排期的 playbook + 例会与告警制度。
> 每条都写清「读哪张表 / 调哪个工具 / 阈值多少 / 输出什么」，不做泛泛而谈。

## 一、六个新增角色（每个都有独立交付物）

| # | 角色 | 只回答一个问题 | 主要数据 | 交付物 | 节拍 |
|---|---|---|---|---|---|
| 5 | **广告投放优化师** | 钱花在哪、该加还是该撤？ | `sif_ad_campaign_week`、`sif_ad_group_keyword`、`market_assess_keyword_promotion`（出价区间/盈亏平衡） | 加/减/关 三档清单，每条带出价区间与盈亏 CVR | 每周 |
| 6 | **竞品情报官** | 对手在动什么？我该跟还是让？ | `sif_competitor`、`ads_get_asin_campaign_changes`（新建 campaign 事件）、`market_discover_competitors`（价格带/评论门槛/姿态） | 竞品动向周报：谁新车、谁降价、谁在抢我的头词 | 每周 |
| 7 | **变体矩阵管理员** | 哪个变体吃哪个词？ | `sif_asin_keyword`（按父体聚合）、`ops_get_listing_traffic_structure`（按 color/size 拆）、`ops_get_listing_keyword_distribution` | 变体 × 词 的分配表 + 重复占位/自相残杀的清单 | 双周 |
| 8 | **供应链 / 补货计划员** | 什么时候必须到货？ | `sif_sales_month`、`sif_traffic`（周）、`sif_keyword_demand.weeks_to_peak` | 补货时间轴（按旺季倒推）+ 断货风险清单 | 每月 |
| 9 | **新品冷启动经理** | 90 天能不能起？ | `sif_asin.first_available_day`、`sif_keyword_aba`、`market_screen_keyword_opportunities` | 冷启动 90 天里程碑（词量/自然位/评价数） | 每周 |
| 10 | **数据口径守卫**（内部） | 这批数字能不能用？ | `sif_raw`、`sif_sync_run`、`sif_quota_log` | 口径变更告警、缺失周清单、点数超支预警 | 每次同步后自动 |

再补两个**交叉角色**，不新增表，只换读法：

- **内容 / Listing 优化师**：把 `sif_asin_keyword` 里「已带量但没进首页」的词交给 amazon-ops 的 Listing 草案去埋；不自己改文案。
- **财务 / ROI 分析师**：`market_estimate_profit_threshold` 反推采购上限 + `sif_asin.price` 与 `sif_competitor.price` 比价带 + 广告花费估算，产出一张「这个 SKU 还能不能做」的单页。

## 二、十套 playbook（可排期、有触发条件）

| # | 场景 | 触发条件 | 动作序列 | 验证口径 |
|---|---|---|---|---|
| P1 | **流量掉了（24h 处置）** | 周环比 ≤ -25% | ① 看自然/广告拆分 → ② 假下滑(广告停)只查广告结构 → ③ 真下滑调 `analyze_traffic_anomaly`(10 点) → ④ 出 1 页结论 | 次周 total 回升或明确归因 |
| P2 | **头词卡位攻坚** | 份额 ≥5% 且自然位 ≥ p2 | ① 该词单开精确/词组 → ② 算盈亏平衡 CVR → ③ 补 Listing 相关性 → ④ 每周看 p2,11 → p1,xx | 自然位进首页 + 自然分占比升 |
| P3 | **广告依赖戒断** | 近 4 周 ≥2 周 ad_ratio ≥0.6 | ① 停最差 ad group → ② 把预算挪给已带量的自然词 → ③ 监控自然分是否补位 | ad_ratio 降到 0.5 且 total 不掉 |
| P4 | **关键词生命周期** | 每月全量体检 | candidate→active→assigned→used→observing→retained/paused/excluded/archived（与 amazon-ops 的 kw lifecycle 同名同义，双向对齐） | 每个词都有「下一状态」，不能悬空 |
| P5 | **变体矩阵** | 变体 ≥3 个 | 按 color/size 拆流量，找「重复占位」与「零流量变体」 | 每个词有唯一主变体 |
| P6 | **季节备货** | `weeks_to_peak ≤ 12` | 倒推：生产周期 + 头程 + 上架 → 备货量按去年同季周量 × 目标份额 | 旺季前 4 周库存到位 |
| P7 | **竞品攻防** | 竞品新车/降价事件 | 跟（同词加价）/让（换词）/打（差评痛点）三选一，写理由 | 事件后 2 周份额变化 |
| P8 | **多站点复制** | 同 ASIN 已在 US 验证 | 复制词表→本地化→单独建 `marketplace` 维度数据 | 新站点 8 周内出第一页自然位 |
| P9 | **新品 90 天** | `first_available_day` 在 90 天内 | D0-15 铺词 + 评价；D16-45 抢 p2 词；D46-90 打头词 | D90 自然流量占比 ≥30% |
| P10 | **季度预算分配** | 每季度末 | 按「每点带来的自然位提升」排序 ASIN，砍尾部、加头部 | 季度点数 ROI 提升 |

## 三、例会制度（把数据变成节奏，而不是变成报表垃圾）

| 会议 | 时间 | 桌面上的东西 | 产出 |
|---|---|---|---|
| 早会 10 分钟 | 每日 | 看板首屏：昨日 total、自然/广告比、触发阈值的事件 | 今日 1-3 件待办 |
| 周会 30 分钟 | 周一 | 周报 7 段 + 缺口词 Top5 + 广告增删清单 | 本周主攻词、预算调整 |
| 月度复盘 60 分钟 | 月初 | 关键词体检 + 竞品动向 + 补货时间轴 | 词表增删、备货计划 |
| 季度规划 | 季末 | `weeks_to_peak` 排期 + 点数 ROI | 下一季 ASIN/预算分配 |

## 四、告警（插件里要做的 M6 模块，先写清规则）

| 告警 | 条件 | 阈值可配 | 送达 |
|---|---|---|---|
| 流量急跌 | 周环比 ≤ -25% 或 自然分周环比 ≤ -20% | 是 | 页面红条 + 会话提醒 |
| 广告依赖 | 连续 2 周 ad_ratio ≥ 0.6 | 是 | 页面黄条 |
| 缺口扩大 | 头词自然位后退 ≥ 8 位 | 是 | 页面黄条 |
| 数据陈旧 | 最新 `data_date` 落后 ≥ 2 天 | 否 | 页面灰条（说明 SIF 侧延迟） |
| 点数超支 | 日消耗 > 日预算 或 余额 < 15% | 日预算可配 | 页面红条 + 阻止 L2/L3 |

## 五、模块与角色的对应（下一步排期用）

| 模块 | 内容 | 服务哪些角色 |
|---|---|---|
| M3 存储 | SQLite 建库 + 迁移 + 查询视图 | 全部（地基） |
| M4 同步 | L1/L2/L3 importer + 预算闸 + 缓存 | 数据守卫、运营 |
| M5 看板 | 流量曲线、缺口表、ABA 动量 | 运营、数据分析 |
| M6 告警 | 上表五条规则 + 页面提示 | 运营、数据守卫 |
| M7 报告 | 日报/周报/专项 模板生成并入库 | 全部 |
| M8 竞品 | 竞品动向墙（campaign 变更 + 价格带） | 竞品情报官、市场分析 |
| M9 词库 | 关键词生命周期 + 与 amazon-ops 双向对齐 | 关键词研究员 |
| M10 财务 | 采购上限反推 + ROI 单页 | 财务/ROI |

**优先级建议**：M3 → M4 → M5（先把「能看数」跑通）→ M7（能出报告）→ M6/M8/M9/M10（按需）。
先做 M3/M4 还有一个现实理由：**M3 建库之后，所有分析都是 0 点**，钱只花在采集那一次。
