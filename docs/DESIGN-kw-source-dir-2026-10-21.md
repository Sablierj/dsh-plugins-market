# 关键词数据源目录 —— 设计与落地（2026-10-21 · v2）

> 需求方两条追加要求：
> 1. **目录结构可以固定**，以后只在里面新增不同月份的数据；
> 2. 根目录**可以在插件里指定存放位置**，并且**能在插件里选择读取目录**。
>
> 这份是 v2，把 v1 的"目录即类型"落到固定结构上，并补了目录选择器。

---

## 一、发现了什么（实测）

WSL（Ubuntu 24.04）里有一套在跑的亚马逊运营系统：`~/.openclaw/amazon-ops-hub`。
关键词数据源目录已经存在，而且**正好补上插件缺的两块数据**：

```
03-knowledge/keywords/master/source/
├── brand-terms/      7 个   ROFIEJOX_搜索查询绩效_品牌视图_*.csv   ← ABA
├── search-terms/     5 个   深谷-us-sp/sb-搜索词-*.xlsx           ← 广告报表
├── sellerjingling/  23 个   竞品关键词数据ASIN-US-B0*.xlsx         ← 卖家精灵
└── xiyou/            2 个   关键词反查结果_US_B0*_*.xlsx           ← 西柚
```

Windows 侧可直接访问（两个写法都实测可用）：

```
\\wsl$\Ubuntu\home\open\.openclaw\amazon-ops-hub\03-knowledge\keywords\master\source
\\wsl.localhost\Ubuntu\home\open\.openclaw\amazon-ops-hub\03-knowledge\keywords\master\source
```

实测表头：ABA 一份月报 **2,500 词**，列含 **搜索查询数量（=搜索量）**、搜索查询分数（排名）、
曝光量/品牌占比、点击量/点击率/品牌占比 —— 正是 `kw_master.aba_*` 要的。

## 二、固定的目录结构（这就是契约）

从今往后**结构不变**，只往里加文件。四个子目录，名字必须一字不差：

```
<根目录>/
├── brand-terms/         ABA 搜索查询绩效（品牌视图）     → brand_terms
├── search-terms/        SP/SB 搜索词报告                → ad_report
├── sellerjingling/      卖家精灵 ASIN 反查              → competitor_sellersprite
├── xiyou/               西柚 关键词反查                 → competitor_xiyou
└── (可选) manual/       手工整理的关键词清单             → keyword_list
```

**目录名 = 解析器**，文件名不再决定类型。规则按优先级：

1. 文件在四个子目录之一 → 用那个目录的类型（**不看文件名**）
2. 根目录直接放的文件 → 退回文件名识别
3. 都不认识 → 标成「未识别」，**不猜**，并提示「把它移到对应子目录」

> 这一条解决的是实测到的真问题：卖家精灵真实导出叫 `ReverseASIN-US-B0GV55Q4JG-Last-30-days.xlsx`，
> 现有规则一条都不匹配，会退化成纯词表，**排名与竞品事实全丢**。

### 以后只加文件，不加结构

新增月份的数据 = 往对应子目录里放文件。界面按**文件名里的日期**归月
（`..._2026_03_31.csv`、`...-20260328.xlsx`、`..._202607.xlsx`），
列成「2026-03 / 2026-04 / …」的时间轴，方便按月增量导入。

## 三、根目录：三件事都要有

### 3.1 默认值

```
\\wsl$\Ubuntu\home\open\.openclaw\amazon-ops-hub\03-knowledge\keywords\master\source
```

存进设置项 `kw.sourceDir`，**空 = 用这个默认值**（不是"没有"）。
「恢复默认」把它清空即可。

### 3.2 在插件里选目录（这是新增的核心）

浏览器出于安全限制**拿不到**用户选中目录的绝对路径（`<input webkitdirectory>` 只给相对路径）。
所以选择动作必须由 **Host 侧**完成。插件是纯 Node ESM（已经在用 `child_process` 起浏览器），
可以直接弹系统原生对话框：

```
页面「选择目录」按钮
   → POST /api/kw/source-dir/pick
   → Host 弹原生文件夹选择框（并定位到当前根目录）
   → 用户选完 → 返回绝对路径 → 写入 kw.sourceDir → 立即重新扫描
```

三级回退，哪一级成了就用哪一级：

| 优先 | 做法 | 说明 |
|---|---|---|
| 1 | `Shell.Application.BrowseForFolder`（PowerShell COM） | Windows 上最稳，会把窗口带到最前 |
| 2 | `System.Windows.Forms.FolderBrowserDialog -STA` | 回退；个别环境会被挡在后面 |
| 3 | 手动输入框 + 「校验」 | 无桌面/对话框被拒时用；输入后立刻校验结构 |

**对话框被取消**要返回"未选择"，不能返回空串再被当成"清空设置"——
两者差得很远。

### 3.3 选中之后立刻校验结构

选完（或手输完）马上检查四个子目录在不在，缺哪个说哪个：

```
✅ 目录可读
✅ brand-terms      7 个文件
✅ search-terms     5 个文件
⚠️ sellerjingling   不存在
⚠️ xiyou            不存在
                          [创建缺失的 2 个目录]
```

「创建缺失目录」只建**空目录**，不写任何文件，不问就直接建（可逆、无副作用）。
但**不会**替用户猜根目录对不对 —— 一个都没有时只说"这不像关键词数据源目录"。

## 四、界面：关键词管道页三块

### 4.1 数据源目录卡（页首）

```
数据源目录
  \\wsl$\Ubuntu\...\master\source        [选择目录] [打开目录] [重新扫描]
  默认路径 · 未修改

  ✅ 目录可读 · 37 个文件 · 4 类 · 已导入 0 · 未导入 37 · 上次扫描 19:30

  ┌────────────────┬──────────┬──────┬────────┬──────────────┐
  │ 子目录          │ 类型      │ 文件  │ 已导入  │ 最近文件       │
  ├────────────────┼──────────┼──────┼────────┼──────────────┤
  │ brand-terms    │ ABA      │   7  │   0    │ 2026-03      │
  │ search-terms   │ 广告报表  │   5  │   0    │ 2026-04-16   │
  │ sellerjingling │ 卖家精灵  │  23  │   0    │ 2026-06-01   │
  │ xiyou          │ 西柚      │   2  │   0    │ 2026-07      │
  └────────────────┴──────────┴──────┴────────┴──────────────┘

  [导入全部未导入]   [只导入最近 30 天的]
```

三个按钮的分工：

- **选择目录**：弹系统对话框，选完写设置 + 重新扫描
- **打开目录**：资源管理器打开当前根目录（不是选，是去看）
- **重新扫描**：只读，重列文件与状态

### 4.2 文件清单（展开）

一行一个：`文件名 · 类型 · 大小 · 月份 · 状态 · 操作`

状态四态，与本仓其他模块一致：

| 状态 | 含义 | 下一步 |
|---|---|---|
| **未导入** | 扫描到了，没导过 | 导入 |
| **已导入** | 内容 hash 在库里（再导是 no-op） | 查看 / 重导 |
| **未识别** | 目录与文件名都判不出类型 | 移到对应子目录，或手动指定类型 |
| **解析失败** | 解析器报错 | 看一行原因 |

### 4.3 目录设置

- 当前值 + 是否默认
- 「选择目录」/「恢复默认」/ 手输 + 校验
- 允许 Windows 路径、`\\wsl$\...`、已映射盘符（`Z:\...`）

## 五、工具：不新增，扩一个 action

`amzn_kw_source` 已有 `list / exclude / include`，加一个：

```
amzn_kw_source  action = 'dir'
    path?       不给就用 kw.sourceDir（空则默认 WSL 路径）
    recursive?  默认 true
→ 目录是否存在 / 用的是默认还是自定义 / 四个子目录的类型与文件数 /
  文件清单（名字、大小、mtime、月份、状态、类型）/ 结构问题（缺哪个子目录）
```

导入仍只走 `amzn_kw_import({ path: 目录 })`，按内容 hash 幂等。

**为什么不合并成一个动作**：扫描是读、导入是写。合成一个，人就没法在导入前先看清单。

**目录选择不进工具**：它要弹 GUI，属于页面上的动作（`POST /api/kw/source-dir/pick`），
不给 agent 一个"能弹窗"的工具 —— 那会让一次工具调用卡住等人点鼠标。

## 六、链路

```
根目录（固定四子目录）
   ↓ amzn_kw_source(action='dir')      读：有什么、认不认得、结构全不全
   ↓ amzn_kw_import({ path: 目录 })     写：按子目录定类型 → 解析 → 事实表（hash 幂等）
   ↓ amzn_kw_merge                      算：重算 kw_master（ABA/广告/竞品三源合并、分层、SOP 标记）
   ↓ amzn_kw_pipeline_run               产：标题 / 五点 / 后台 / 广告 / 否词 五套 CSV
```

**增量**：文件按内容 hash 识别，同一个文件导两次是 no-op；
不同月份的同名报表是**两份事实**，按日期并存，不被覆盖。

## 七、失败态（先说清，免得以后当 bug 修）

| 情况 | 表现 | 不能怎样 |
|---|---|---|
| WSL 没启动 | 「目录不可达 —— WSL 可能没启动」，附启动命令 | 不能显示「0 个文件」 |
| 选了不存在的路径 | 指出改的是哪一项，不回退 | 不能静默换成默认 |
| 子目录缺失 | 逐个列出，可一键创建空目录 | 不能假装结构完整 |
| 对话框被取消 | 「未选择」，设置不变 | 不能当成清空 |
| 超大 xlsx（7 MB） | 导入时给进度与耗时 | 不能无提示地卡住 |
| 同一 ASIN 多日期 | 全部入库，按日期区分 | 不能后一份覆盖前一份 |

## 八、落地顺序

| 阶段 | 做什么 | 为什么这个顺序 |
|---|---|---|
| **P0** | 设置项 `kw.sourceDir`（默认 WSL 路径）+ `amzn_kw_source(action='dir')` + 管道页目录卡 + 「打开目录」 | 先让人**看得见** |
| **P1** | 「选择目录」（原生对话框 + 三级回退）+ 结构校验 + 一键补空目录 | 换目录是低频动作，但要能自己做 |
| **P2** | 按目录类型批量导入 + hash 幂等 + 文件状态与月份轴 | 看见、能换之后，才敢一键导 |

---

## 九、这份设计证明不了什么

- 没有验证 37 个文件**全部**解析成功（抽验了 ABA 表头、`sellerjingling` 与 `xiyou` 各一份 dryRun）。
- `search-terms/` 里两份「数据聚合-ASIN-搜索词(0)-*.xlsx」名字带 `(0)`，含义未知，导入时才知道。
- 原生对话框方案是按 Windows + PowerShell 设计的；换平台（mac/Linux）要走各自的原生选择器，
  这一份没有覆盖。
- 目录结构是**那套系统的现状**。现在把它固定成契约，意味着**以后它改结构，这里要跟着改**。
