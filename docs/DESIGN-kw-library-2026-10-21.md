## 二、现状诊断：66 列里有 3 个致命空缺

`kw_master` 的设计已经很全（66 列）：搜索量/ABA 品牌份额/广告效率（CTR/CVR/ACOS/ROAS/CPC）/
竞品名次/漏斗/分层/优先级/机会分/SOP 落位。但实测填充率暴露了真问题：

| 列 | 填充率 | 判断 |
|---|---|---|
| 广告聚合（曝光/点击/订单/花费） | 100% | ✅ |
| CVR / CPC / CTR / ROAS | 95% / 72% / 70% / 70% | ✅ 合理（没有订单就没有 CVR/ACOS） |
| 搜索量 | 40% | ✅ 合理（长尾词没有 ABA） |
| ACOS | 5.7% | ✅ 合理（21,421 个有花费的词里只有 1,744 个有订单） |
| **listed_volume / listed_difficulty** | **0%** | ❌ 声明了但没人写 —— 死列 |
| **词角色（有没有"这是不是我"这一列）** | **不存在** | ❌ **最致命** |

### 致命在哪：标题资格只看搜索量

`forListing()` 原来的规则是 `标题 = 搜索量 ≥ 10,000 且 层级 ≤ L3`。**完全不看相关性。**

实测后果（加角色之前）：

```
够格进标题的词: 219
  含 bench 且含 cushion:   8  (4%)
  两者都不含:             95 (43%)   ← 主身份稀释
  最典型的: patio furniture set 1,674,092 / outdoor pillows 1,168,442 /
           chair covers 770,854 / pillow 451,843 / loveseat 236,649
```

**这与 2026-05 Alexa for Shopping 之后的排序逻辑正好相反**：系统看的是"证据是否都指向
同一个产品身份"，而把"户外家具套装""椅套""枕头"写进长凳垫的标题，是把主身份冲淡。

根因在产品线信号：`bench-cushion` 的内置 core 是一袋散词
`['bench','cushion','pad','pillow','seat','outdoor','window sill','bay window','patio']`
—— 命中任意一个就算这条线，于是 `patio furniture set` 因为含 `patio` 就被算成"长凳垫"。

## 三、设计：词角色（role），产品线 id 就是身份短语

新增两列（迁移 v51）：

| 列 | 含义 |
|---|---|
| `role` | `identity` / `partial` / `offline` / `unknown` |
| `role_basis_json` | 判定依据：命中了哪些身份词、缺了哪些、产品线是谁 |

**规则**：`bench-cushion` → 必须**同时**含 `bench` 与 `cushion`（允许复数与 pad 等近义）。

| role | 含义 | 标题 | 五点 | 广告 |
|---|---|---|---|---|
| `identity` | 身份短语完整命中 | ✅ | ✅ | ✅ |
| `partial` | 只命中品类的一部分（含 cushion 不含 bench） | ❌ | ❌ | ✅ |
| `offline` | 一个身份词都没命中（patio furniture set） | ❌ | ❌ | ✅ |
| `unknown` | 这条线没有可解析的身份短语（如中文 id） | ❌ | ❌ | ✅ |

**关键取舍：只关掉自然位，不关广告位。** 泛词搜索量大、转化可能真实存在，
只是不该出现在标题里 —— 一刀切砍掉会把流量也砍了。

## 五、还没做（下一批）

1. **商品身份词要人工确认一次**：`bench-cushion` 的 identity 短语现在是自动从 id 推的，
   但真实品类可能有同义说法（bench pad / bench seat cushion）。需要一个"确认身份短语"的入口。
2. **竞品品牌词**：现在没有品牌黑名单。卖家精灵的 `top10Asin` 与西柚的品牌词可以用来
   标记 `brand` 角色（不可进标题，可做竞品词广告）。
3. **场景/任务标签**：Alexa 时代要的是"人群 + 场景 + 任务"，现在只有 `modifiers_json`
   记录了 outdoor/indoor 这类修饰词，没有结构化成场景标签。
4. **listed_volume / listed_difficulty 两个死列**：要么接上写入，要么删掉。
5. **3 对广告报告周期重叠**：仍会计重复，需要用 `amzn_kw_source` exclude。
