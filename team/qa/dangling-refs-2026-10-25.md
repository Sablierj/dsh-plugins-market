# 悬空控件引用清单（dangling control refs）2026-10-25

> 席位：独立复验席（verifier）。**只读审计**，未改 `src/**`、`tests/**`。
> 范围：**面向用户或 agent 的文案**里，指向某个不存在的控件（或指向被移除的位置）的引用。不查功能缺口，不查「实现缺不缺」。
> 判定只用三种：**悬空**（控件/位置不存在）/ **半悬空**（控件在，位置写错）/ **待确认**（判不出，如实记）。

## 0. 病根：一次「只改了一部分」的移除

**2026-10-21 右栏被整块拆掉**（`src/web/page.js:345-349`）：

```
/* 2026-10-21：右栏（当前选中 / 丢给 agent / agent 动态）整块拆掉。
   需求方的原话是「在对话里说即可，这个完全没啥作用」…… */
main { display:grid; grid-template-columns:170px minmax(0,1fr); … }
```

证据：`page.js` 现在**没有任何 `<aside>` 被渲染**；`main` 只有 `170px + 1fr` 两列。右栏里的三个控件（当前选中 / **丢给 agent** / agent 动态）与 promptBox 一并消失。

**而引用它的文案只改了一部分**——仓库自己知道这件事：
- `src/web/pages/research.js:427`：「2026-10-21：右侧栏拆掉之后**没有 promptBox 了**……」
- `src/web/page.js:438`：「复制之类的动作原来靠右侧栏那句 aria-live……右栏拆掉之后改成……」

**「知道之后只改了一部分」比「不知道」更贵**：后者下次会被发现，前者会被当成已经修过。下面 5 条都是这句话的注脚。已修的那条（`optimize.js` 旧文案「用右侧「跑优化」」）是同类病灶的第一处，下表不再列（它已修）。

## 1. 悬空引用逐条

### D-1 · `asin.js:2636` — 右侧「跑采集」【悬空】

- **原文**：`'在对话里说「采集这些 ASIN：B0…」，或先在 ASIN 库选中若干行，再用右侧「跑采集」生成 prompt。'`
- **文件:行**：`src/web/pages/asin.js:2636`
- **它指着的控件**：「右侧」= 已拆除的右栏（`page.js:345-349`）。「跑采集」这个名字只在 `src/domain/optimize/prompt-seed.js:81/87` 作为 **prompt 种子的 label** 存在（`{ module: 'asin', label: '跑采集', … }`），**它从来渲染在被拆掉的右栏里**。现在没有任何 UI 元素叫「跑采集」。
- **修法**：删掉「右侧」那半句，只保留「在对话里说」路径（与 `optimize.js` 已修的那句同款改法）；如果「跑采集」prompt 按钮确实在某个模块页还有，先证实在哪一页，再写清页名。

### D-2 · `research.js:84` — 右侧「丢给 agent」里的「扩词入库」【半悬空】

- **原文**：`'勾选后点右侧「丢给 agent」里的「扩词入库」，由 …'`
- **文件:行**：`src/web/pages/research.js:84`
- **它指着的控件**：「扩词入库」**真的存在**——`src/web/page.js:1034` 的 `<button id="rsImport">扩词入库</button>`，在 **research 页顶的工具条**里（`rsSeed` 旁边），**不在右栏**。「丢给 agent」是被拆掉的右栏容器名。
- **修法**：改为「勾选后点上面工具条的「扩词入库」」——控件是对的，位置是错的。半悬空比悬空更隐蔽：读者会去找一个不存在的容器，而正确按钮就在他眼前。

### D-3 · `prompts.js:1523` — 「到右侧复制发送」【悬空】

- **原文**：`'已生成 prompt（' + picked.length + ' 个词，站点 ' + marketplace + '），到右侧复制发送。'`
- **文件:行**：`src/web/pages/prompts.js:1523`
- **它指着的控件**：右栏的 promptBox（用于「塞进框再复制」）**随右栏一起拆了**——`research.js:427` 原文承认「右侧栏拆掉之后没有 promptBox 了，所以这里不再『先塞进框再复制』」。**research 页改了，prompts 页这句没改。**
- **修法**：prompt 生成后给页内一个复制入口（button + aria-live 播报，同 `page.js:438` 后来的方式），或改文案说明 prompt 出现在哪里、怎么复制。**不能只删「右侧」两个字**——那句的动词是「复制发送」，删了位置词句子还是假的。

### D-4 · `tools/prompt.js:183` — 「「丢给 agent」按钮」【悬空，工具输出，最高优先】

- **原文**：`'这条会出现在工作台对应模块的「丢给 agent」按钮里，下一次刷新页面就变。'`
- **文件:行**：`src/tools/prompt.js:183`
- **它指着的控件**：「丢给 agent」按钮 = 右栏的按钮，**已随右栏拆掉**。
- **为什么这条最要命**：这是**工具输出**（`amzn_prompt_upsert` 的回执文案），不是页面文案。**agent 读到它会照着给人指路**——人会去页面找一个不存在的按钮。页面谎话骗人，工具谎话骗 agent，agent 再转述给人，谎言有中转。
- **修法**：改成实际入口（提示词专区 `prompts` 页的提示词列表；用户点「丢给 agent」这条路径已废）。改之前先确认「这条 prompt 现在怎么被使用」——如果使用路径本身已经断了，要连使用路径一起报，不只是改文案。

### D-5 · `policy.js:113` — 「右侧选一条关联」【待确认】

- **原文**：`'<div class="rule-sect">受政策影响的规则（点 × 解除，右侧选一条关联）</div>'`
- **文件:行**：`src/web/pages/policy.js:113`
- **它指着的控件**：**判不出**。这里的「右侧」可能是面板内部布局（规则行右侧的关联选择器），也可能是已拆右栏的残留。我没渲染这个面板去看 DOM 布局，**如实记为待确认，不猜**。
- **确认方法**（给下一个人）：打开 policy 页「受政策影响的规则」区块，看「选一条关联」的选择器/下拉在该区块的哪一侧。若在行内 → 把「右侧」改精确（「行末」/「行右侧」）；若不存在 → 按 D-1 修法。

## 2. 反面谎话：声称一个不存在的控件「存在」（同一病根的另一方向）

这类不是「指向不存在的」，而是**替一个不存在的控件背书**。按 lead 的第 5 项要求一并扫了：

### D-6 · `optimize.js` 空态文案 vs 同文件的开跑按钮【在飞，落地前自相矛盾】

- **原文 A**（`src/web/pages/optimize.js:150-151`）：`'…开跑这一步目前只能在对话里说（页面还没有开跑按钮）…'`
- **原文 B**（同文件 `:153-175`）：渲染 `'<button type="button" data-optstart="1">开跑这一轮</button>'`（三种态：disabled / 被阻断 / 可点）
- **判定**：同一文件里 A 说「没有开跑按钮」、B 把按钮画了出来。**dev-11 的在飞工作**（开跑按钮 + `optimize-prepare` 路由）正在替换这句话——`T83-⑦` 那条红就是「替换中」的证据。**不是 def 缺陷，但不许就这样落地**：等 dev-11 收口时确认 A 被删干净、或改成与 B 一致。
- **给 dev-11 的验收句**：空态文案与「开跑这一轮」按钮**不许同时存在**；全仓 grep「页面还没有开跑按钮」应为 0 命中。

### D-7 · 「页面跑优化按钮」的命名漂移【待确认，低优】

引用了「页面跑优化按钮」的位置：`src/domain/asin/health.js:446`、`src/web/routes.js:306`、`src/web/routes.js:2947`、`src/tools/asin-health.js:71`、`src/tools/report.js:35`、`src/domain/audit/targets.js:2048`。

- **情况**：dev-11 的按钮 label 是「**开跑这一轮**」，这些位置叫它「**跑优化按钮**」。按钮落地后「页面跑优化按钮」这个指代**不再悬空**，但**名字对不上 label**。
- **判定**：**待确认**——如果这些注释/文案指的是同一个按钮，把称谓统一成「开跑」；如果指的是另一个「跑优化」按钮（`prompt-seed.js:132` 的 `label: '跑优化'` 是 prompt 种子，不是页面按钮），那 D-7 升级为悬空。**判不出，不猜。**

## 3. 给下一轮的两条守门建议（这类病根的治法）

1. **源码级守门**（便宜）：一条断言扫页面与工具输出的渲染文案——凡出现「右侧/左侧/上方/下方 + 控件名」的句子，控件名必须能在页面源码里作为 label/id 找到。我这次的扫描器是启发式（「…」内名字 + 引号外 0 命中），可直接固化成 t8x。
2. **移除守门**（治本）：拆掉一个 UI 区块的提交里，`grep` 该区块控件名必须全仓清零；`research.js:427` 与 `page.js:438` 这两处「知道」的注释就配「引用处已清点」的清单。D-1…D-4 的共同病因是**移除的提交只改了邻近文件**。
