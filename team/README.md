这个目录里的东西**跟代码一起进 git**，因为它被源码注释直接引用，读者必须能在仓库里解析到。

## 两个根，别再混了（2026-10-25 定）

| 位置 | 放什么 | 在 git 里吗 |
|---|---|---|
| **本目录**（`amazon-ops/team/**`） | 被源码注释引用的文档：决策（`decisions/`）、清理台账与复验报告（`qa/`）、逐单交付报告（`dev/`） | **是** |
| 工作区 `…\deepseek-harness\default-workspace\team\**` | 更大的团队文档库：需求、概要/详细设计、测试计划、标准规范、产品材料 | 否 |

**规则**：源码注释只许引 **本目录** 内的路径。
以前 `src/domain/keywords/competitor.js` 与 `src/domain/reports/spend-monthly.js` 引的
`team/qa/fallback-zero-backlog-2026-10-25.md` 当时只存在于工作区，**在仓库里解析不到**——
那正是本仓反复在修的那类「声明了但没落地」。现已搬入本目录。

## 目录约定

- `decisions/` —— 拍板记录。**已拍板的内容不涂改**；改判另起一节，写明依据与日期。
  受托决定（由交付方代拍）必须写明「这是受托决定，不是需求方逐条签字」。
- `qa/` —— 清理台账、独立复验报告、冻结清单。
  - 台账类文件必须**逐条给归宿**：已修 / 判为误报（给理由）/ 待修（给风险与单号）。
    不许有「看着不顺眼但没管」的第四条。
  - 复验报告必须写清**哪部分签、哪部分不签**，以及**没取得的数字**（不许写「应该」）。
- `dev/` —— 每单的交付报告（五段式：需求 → 做法 → 证据 → 未验证项 → 回滚）。

那行数字才算数。清单样例见 `qa/sha256-pre-freeze-2026-10-25.txt`。
