## 三、一个可读性缺陷（我自己中招了，但不是我粗心）

**R-3（P2）：空值留白会让「整列为空」的那一列视觉塌陷，人眼把后一列读到前一列**

我第一遍读四象限时，把 `bench cushion` 那行的 **竞品最好排名 4 读成了我们的排名**，
据此差点报一个不存在的 bug。查证据块才发现：那一行**我们排名是空的**。

**先说清一处我自己的更正**：我一开始把这写成「列会错位」——**不对**。
`table()` 的列宽是按显示宽度算的，坐标是齐的。**塌的不是坐标，是认知**：
一整列全空，眼睛跳过它，把后一列的数字补到前一列。所以「对齐」断言管不了这件事。

改前（空值留空）：
```
关键词                  搜索量     我们排名  竞品最好排名
bench cushion        73,233        4            ← 4 是竞品的，看着像我们的
```
改后（空值印 `—`）：
```
关键词               搜索量  我们排名  竞品最好排名
bench cushion        73,233  —         4          ← 一眼看出「我们没有」
```

**修法**：`src/tools/render.js` 的 `table()` 空值印 `—`（原来注释写「dropping empty cells
so narrow results stay narrow」——省几个 token 是真的，但代价是**读错列**，可读性赢）。
一处改，所有 `text()` 输出受益（四象限、采集详情、健康摘要、ASIN 列表）。

**测试 `t87-table-empty-cell.mjs`（6 条）**，其中最贴的一条不是「列对齐」，
而是直接钉症状：**「竞品排名不许落进『我们排名』列」**。
