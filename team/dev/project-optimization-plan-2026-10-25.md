**处置**：req-owner 出 PRD 勘误清单（**不改 v1.3 原文**），逐条写「原文状态 → 实际状态 → 证据文件:行」。

### P-2 · PRD 里唯一可量化的流程指标，从来没人测过 —— **P1，本轮就测**

`G-2` 的判据写的是：「**进入主流程点击预算 ≤5**」。
全仓 2600+ 断言里，**没有一条在测「点击几次」**——我们一直在测数字对不对，没测过**流程走不走得下去**。
而需求方今天亲口说的「感觉与原型不一样」，本质上就是**流程体感**问题。

**处置**：把「点击预算」变成一条可执行验收（见第三节 E-1）。测不出来就写「未取得」，不编。

### P-3 · O-04「定制品类规则」待拍板，而定制正是这门生意的核心 —— **P1，需要拍板**

PRD 明确：`O-04 定制长凳垫优化分支（尺寸/价格区间/交付期信任表达）是否立规则 —— ⏳ 待拍板，本期不立规则`。

但需求方的产品就是**定制坐垫**（`Custom Size Bench Cushion, 75D High Density Foam Filling`）。
**不立规则 = 优化器对核心品类没有判定**，只能套通用文案规则。这是**业务级缺口**，不是文档问题。

**我的建议**（可被否）：先立三条**最小**规则，不追求完整品类模型：
1. **尺寸可定制必须写明**：标题/五点里出现可定制信号（`custom size` / `made to order` / 尺寸范围）——缺失则告警；
2. **交付期表达**：定制品必须给出交期或「按下单后生产」的表述，否则买家无法判断；
3. **不可退换须对冲**：定制品常不可退，若正文无「确认尺寸/下单前沟通」类对冲表述，告警。
（对应 `src/rules/listing-rules.js` 的 lexicon/threshold 两类，**不需要写代码解析尺寸**。）

## 二、原型优化方案（4 条，都是设计判断，不是美化）

| # | 问题 | 方案 |

| A-1 | **五块里四块回答同一个问题**（摘要 / 待决策 / 异常队列 都在说「今天干什么」） | 合并成**一条主导**：「今天要做的事」列表（最多 5 条，每条带「已等多久 + 下一步」）；健康矩阵降为**概览带**；最近变化收进折叠区 |

| A-3 | 待决策收件箱把**补数请求**（缺数据）和**门禁/草案/偏离**（人做决定）混在一起 | 补数请求移出收件箱，归入「**数据缺口**」（与健康卡的「缺 N 个字段」同类）；收件箱只收「需要人做决定」的四类 |
| A-4 | **没有空态规格**：原型全是样例数据，而空库是早期常态 | 补一页「**空库规格**」：每块在 0 数据时显示什么、说什么、引导到哪。**这正是需求方今天觉得「空」的根因** |

> A-1 到 A-3 是**改逻辑**，A-4 是**补规格**。四条都不需要重画视觉。
